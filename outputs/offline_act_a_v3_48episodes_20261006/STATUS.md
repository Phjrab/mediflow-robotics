# ACT-A 48-episode subset and queued training (2026-10-06)

- The original A-v2 dataset (60 episodes, 32,597 frames) remains unchanged.
- A separate 48-episode/24,588-frame LeRobot v3 dataset was built by excluding source episode IDs 0, 16, 17, 18, 21, 22, 27, 28, 43, 45, 54, and 55. Each excluded episode had first sustained >3° body-action motion after 5 seconds in the read-only diagnostic manifest. This is an experiment, not evidence that the excluded demonstrations are bad.
- Output: `work/lerobot_datasets/Supermassive111/Supermassive111_medicine_a_to_basket_a_3cam_v3_48episodes_20261006`.
- Builder: `lerobot_training/build_48_episode_subset.py`; audit: `subset_audit.json` inside the derived dataset. Video files are copied byte-for-byte and retained episode video timestamps are preserved. Numeric normalization statistics are recomputed; source camera image statistics are carried over and are approximate for this subset.
- Validator: `lerobot_training/validate_48_episode_subset.py`. `dataset_validation.json` reports all 24,588 numeric rows, seven copied video SHA-256 hashes, and 72 decoded images across eight episodes/three cameras passed source-to-derived comparison.
- Separate ACT training launcher: `lerobot_training/train_act_a_v3_48episodes_3cam_100k_3060.sh`. Configuration matches the running 60-episode trimmed lead-in experiment: 100,000 steps, batch size 8, three cameras, RTX 3060, checkpoints every 5,000 steps, a distinct output path and W&B run name.
- Automatic dependency watcher: `act-a-v3-48-after-trim05.service` running `lerobot_training/train_48_after_trim05.sh`. It waits for `act-a-v3-trim05-100k.service` to exit successfully **and** produce the final 100,000-step model checkpoint. Only then does it launch the 48-episode training. If the first run fails or its checkpoint is missing, the second run does not start. As of 23:27 KST the first run was at approximately 2,850/100,000 steps and the watcher was waiting.
- On the single RTX 3060 12GB, the first run consumed about 6.6GB VRAM at full GPU utilization. Starting a second run simultaneously could exceed available memory and slow or fail both, so these two runs are sequential. The first run's own progress bar estimated about 12 h 27 min remaining at 2.17 steps/s. The second run will likely need another 12–13 hours at comparable throughput; these are estimates, not deadlines. Keep the computer powered and the user session active. A reboot interrupts transient user services and requires a status check/restart plan.
- W&B browser login is not required for local training; this service writes local checkpoints even if the user cannot open the dashboard. W&B sync should be checked independently. Neither checkpoint is a proven successful robot policy until offline and supervised physical evaluation.
- No robot inference, teleoperation, or motor command was initiated by this operation.
