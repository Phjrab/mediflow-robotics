# MediFlow VLM 효율 최적화 학습 결과 (2026-09-26)

## 결론

Qwen3-VL-2B-Instruct QLoRA 학습을 완료했다. 정답 전용 손실, 클래스 균형 샘플링,
압축 라벨 응답을 적용했으며 1 epoch 체크포인트에서 재개해 총 3 epochs까지 비교했다.
검증 결과 2 epoch가 가장 좋아 최종 후보로 선택하고, 격리 테스트 111장에 한 번 평가했다.

이전 v4보다 자세와 파지 부위 판단은 크게 개선됐지만 약 C를 한 번도 예측하지 못했다.
따라서 이 어댑터를 실제 약 분류, 바구니 선택 또는 로봇 동작에 사용하면 안 된다.

로봇 제어, calibration, ArUco, Depth, 카메라 설정과 Jetson 원본 데이터는 변경하지 않았다.

## 핵심 수정

- 전체 사용자 프롬프트에 걸리던 손실을 제거하고 assistant completion에만 손실 적용
- 375장 한 epoch 크기를 유지하면서 medicine × grasp 9개 조합을 41~42장씩 균형 샘플링
- 32토큰 JSON 정답 대신 `A|upright|lid` 형식의 핵심 라벨만 학습
- `target_bin`은 medicine_id에서 코드로 결정해 불일치 가능성 제거
- 검증에 클래스별 재현율, 균형 정확도, 예측 분포 추가
- 체크포인트 재개 기능을 추가해 첫 epoch를 다시 계산하지 않음
- 자동 테스트 15개 통과

## 성능 제한 원인

현재 데이터는 전체 수량보다 시각적 식별 가능성이 더 큰 병목이다.

- 한 프레임에 약통이 여러 개 있는데 목표 bbox나 마스크가 없다.
- 일부 손목 카메라 프레임은 동일한 뚜껑만 크게 보여 약 A/B/C 구분 단서가 없다.
- `before_grasp` 중에는 그리퍼가 아직 목표를 가리키지 않아 trial 지시 없이는 목표 약통이 모호하다.
- 카메라와 약 종류가 얽혀 있다. 예를 들어 현재 `/dev/video4` 학습 26장은 전부 A다.
- 검수 라벨은 trial의 목표를 알지만 모델 입력에는 trial instruction이 없어, 이미지 단독으로는
  같은 장면에 서로 다른 medicine_id가 붙는 경우가 생긴다.

따라서 다음 개선은 epochs 추가가 아니라 목표 정보 설계를 먼저 바꾸는 것이다. 실제 추론 입력에
목표 약 이름이 항상 주어진다면 그 instruction을 프롬프트에 포함하고, 모델은 자세·파지 부위를
판단하게 해야 한다. 이미지에서 약 종류까지 찾아야 한다면 목표 bbox/crop 또는 다중 카메라 묶음과
약 라벨이 읽히는 근접 프레임을 추가해야 한다.
