# 퇴근 후 소프트웨어 보완 결과 — 2026-11-08

## 쉽게 설명하면

모델이 내는 빠른 목표를 그대로 따라갈 수 없어 잘라 보내던 부분을 개선할 후보를 만들었다. 속도에 맞춰 중간 목표를 만들고, 실제로 전달된 목표를 기준으로 경로 진행을 관리한다. 관절이 안 움직이는데 목표만 앞서가는 경우는 별도로 추종 정체라고 기록한다.

다만 실제 팔꿈치가 작은 목표에서 거의 움직이지 않은 원인은 아직 확정하지 못했다. 이번 작업은 무인 상태였으므로 모터·카메라·serial·정책 추론을 실행하지 않았다. 새 보간 실행 후보는 실제 연결을 코드로 차단했다. 모의 통과를 실제 약통 투입 성공으로 기록하지 않는다.

## 실제 수행

노트북: 코드 작성, Python3.10 문법 확인, 모의 테스트, 저장 행동 재생, 소스/개인정보 검사, 로컬 작업 브랜치 커밋·증분 bundle 생성과 검증.

Jetson: 파일 전용 SSH/SCP, 코드 백업과 배포, 모의 테스트, 저장된 정책 행동으로 가상 관절18건 재생, CPU 경로 생성120회, 진단 래퍼 bash 문법·기본 계획 출력, OS의 서비스·포트 점유 보고 조회. 모델 로드·GPU 추론·장치 연결은 하지 않았다.

## 종료 상태

Astra active, LeLab inactive를 OS 조회로 확인했다. 서비스를 시작·중지·재시작하지 않았다. follower USB 경로는 존재했다. fuser는 권한 제한 경고가 있어 시스템 전체 점유는 UNVERIFIED로 남겼다. 이번 작업은 실제 포트를 한 번도 열지 않았고 장치 연결을 유지하는 백그라운드 작업도 시작하지 않았다.

## 남은 현장 작업과 첫 명령

실제 미세 이동 원인과 성능은 아직 해결 확인 전이다. 현장에서 DC 전원·팔 지지 상태를 확인하고 다음 읽기 진단만 실행한다.

```bash
sudo -v && bash ~/run_servo_readonly_20261108.sh --execute --operator-present
```

READ_CONFIG를 직접 입력한다. 기대 출력은 SERVO_CONFIG_READONLY_COMPLETE, motor_register_writes=0, port_closed=true다. 토크ON·45도 이상·통신 오류·포트 점유면 상태를 바꾸지 않고 중단한다. 다음은 저장 설정과 SDK 최종 목표를 분석한 뒤 별도의 감독 시험 절차를 정하는 것이다. 기존300스텝 명령을 반복하거나 HOLD 기록을 삭제하지 않는다. [현장 한 장 안내](NEXT_ON_SITE.md).
