# v6 지연 개선·dry-run 재검증 — 2026-11-05

**실제 관측+상태 감시를 수행한 v6 dry-run 1회 통과. 모터 쓰기0. live 미실행. 현재 사용자가 직접 할 작업은 없다.**

## 바꾼 것

- 저장된 후처리 파이프라인을 행동50개에 따로 호출하던 구현을 chunk 전체에1회 호출하도록 변경했다. 정규화 수식/단위 변환을 새로 만들지 않았고 원래 unnormalizer와 CPU device processor를 그대로 사용했다.
- 상태 감시는 같은 레지스터의6축 개별 읽기30요청을 동기 읽기5요청으로 묶었다. RAW값 사용, 토크 모두OFF/모드0/45°C 미만/부하200 미만/Status0/오류 중단 조건과 감시 주기는 유지했다. 토크ON/고온을 발견한 뒤 추가 요청을 보내지 않는다.
- v6의 추론/상태 읽기 구현3개만 별도 파일로 교체했다. AST로 main, 수치 판정, home/단위/해시, 시간 제한, 쓰기 차단, 종료 함수가 그대로임을 대조했다. 기존 파일은 보존하고 새 파일을 사용했다.
- 저장된 관측만 계산하는 경로도 마련했다. 이 경로는 로봇/카메라/serial을 열지 않고, 1.667초를 성능 판정으로 기록한다. GPU 장치는 사용한다. 이것을 live 허가로 취급하지 않는다.

## 지연 계측

같은 저장 관측·seed101·저장된 AMP설정으로 순서를 번갈아5회씩 측정했다. 예열은 측정에서 제외했다.

| 경로 | 평균(초) | 최대(초) |
|---|---:|---:|
| 기존 후처리, 저장 관측 | 1.364172 | 1.372881 |
| 일괄 후처리, 저장 관측 | 1.354488 | 1.365445 |

후처리 단계 자체는 약16.176ms→0.757ms였지만 전체 정책 계산 개선은 약10ms에 그쳤다. 실시간 경로의 병목을 후처리만으로 해결했다고 주장하지 않는다.

실제5종 상태 읽기 한 묶음은 개별10.595ms→동기5.721ms였다. 별도 v6 실관측 검증에서는 상태 읽기와 후처리 최적화를 함께 사용해 시간 제한 안에 들어왔다. 이전 실제 관측 GPU 작업은1.752864초로 HOLD했으며, 이번은1.576156초였다. 서로 다른 관측에서의1회 측정이므로 일반적인 속도 개선율이나 반복 안정성으로 확대 해석하지 않는다.

설치된 LeRobot 소스의 근거는 `processor/normalize_processor.py:287,533`, `processor/device_processor.py:72,122`다. CPU device processor의 non_blocking은 false이므로 CPU로 이동한 값을 읽기 전에 전송이 완료된다. 원래 통계 파일/전후처리 설정/모델 가중치는 변경하지 않았다.

카메라는 같은 wrist/Astra/RealSense3대, 같은 데이터 키와640×480 RGB를 사용했다. 저장된 전처리만 camera1/2/3으로 이름을 바꾼다. 현재 RealSense RGB는 검증한 serial `236223023645`, 인터페이스03의 by-path를 사용했다. 깊이 영상 index0을 대신 넣지 않았다.
