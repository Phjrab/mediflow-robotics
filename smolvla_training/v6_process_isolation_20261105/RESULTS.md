# 정책 프로세스 분리 및 현장 준비 결과

## 실제 수행

Windows에서 코드·모의 테스트를 작성했고 Jetson의 기존 SmolVLA 환경에서 새 폴더에 배포·검증했다. 기존 모델·환경·원본 데이터·중단 기록은 수정하지 않았다.

| 검증 | 명령 또는 결과 | 종료코드 |
|---|---|---:|
| 신규 프로세스·목표 검수 모의 테스트 | `python -B -m unittest discover -s . -p 'test_*.py'` — 14개 통과 | 0 |
| 제어·초기화 모의 테스트 | `python -B -m unittest discover -s operator_candidate -p 'test_*.py'` — 28개 통과 | 0 |

## 지연 결과

| 회차 | 정책 worker 측정 | 최종 확인 포함 CSV 측정 | 판정 |

| 2 | 1.423361초 | 1.441100초 | PASS |

기준은50개 행동/30Hz=1.666667초이며 변경하지 않았다. 이전 CPU 후보의1.685~1.693초 HOLD 기록은 기존 보고서에 보존했다. 저장 입력만 비교한 새 후보는 평균1.374329초였다. 실시간 검증3회의 통과가 장시간 운전이나 약통 투입 성공률을 뜻하지 않는다.

새 후보는 GPU 정책 계산을 spawn 프로세스로 분리하고 프로세스별 CPU 스레드 설정을 적용했다. 정책에 robot/bus/카메라 객체를 전달하지 않는다. 자식 프로세스의 로봇·카메라 장치 경로 열기를 차단하는 검사도 모의 검증했다. 별도 OS 보안 경계나 하드웨어 watchdog을 구성했다는 뜻은 아니다.

기존 main의 조건·감시·시간 제한·종료 경로는 AST 대조로 유지했다. 모델 가중치·chunk50·n_action_steps50·AMP·저장 정규화는 바꾸지 않았다. 프로세스 분리와 스레드 설정 각각의 성능 기여도는 따로 측정하지 않았다. 이번 후보의 GPU 최대 메모리는 별도 측정하지 않았다.

## 목표값과 현장 초기화 코드

동기 읽기와 관절별 개별 읽기에서 기존 Goal_Position이 모두0이었다. 보정 범위 안의 현재 위치와 다르므로 원래 재무장 조건은 계속 거부한다.

`operator_candidate/initialize_current_goal.py`는 별도의 현장 전용 시험 코드다. 기본은 계획 출력이다. 실제 실행에는 현장 입회·팔 지지·전원 차단 수단·직접 INITIALIZE_GOAL 입력을 요구한다. 기존 RobotController를 거쳐, 재확인한 현재 원시 위치에 해당하는 정확한 Goal_Position 패킷1개만 허용한다. 100ms를 넘긴 확인값·다른 목표·토크/모드/보정 쓰기·재전송은 차단한다.

예상 밖 토크ON·통신 오류·목표/현재 불일치·정리 오류이면 재시도하지 않고 FIELD_STOP.json을 남긴다. 새 live는 이 기록이 있으면 거부한다. 원래 중단 기록도 유지한다. **이 기능의 실제 모터 쓰기는 NOT_RUN**이며, 실제 성공을 주장하지 않는다.

## 종료 확인·보존

마지막 읽기에서 토크6개0, 최고35°C, 레지스터 쓰기0, 정리 오류0. 포트 비점유·Astra 유지·남은 작업 프로세스0, 원래 중단 기록 해시 보존을 확인했다.

새 실행 준비 코드는 별도 operator_candidate 폴더에 있다. 원본 실행기는 수정하지 않았다. 후보 first_trial.py를 보강할 때는 기존 후보를 `.bak_20261105T234249`로 백업했다. 백업 경로는 `evidence/`의 FIELD_UPDATE_RECEIPT.json에 있다. 실패 기록과 모델·원본 데이터는 삭제하지 않았다.

## 수정 중 오류와 해결

- Windows 한글 소스 읽기 오류1건: UTF-8 명시 후 같은 프로세스 테스트8개 통과.
- 노트북의 의존 폴더 탐색 오류1건: 테스트 프로세스에만 V6_PREP_ROOT를 지정해 해결. 설치·시스템 설정 변경 없음. Jetson에서는 기본 재사용 경로로 통과.
- 로컬 bash가 PATH에 없어 로컬 문법 검사는 하지 못했다. Jetson에서 bash 문법 검사를 통과했다.
- 결과 파일 전송 연결1회 종료: 한 번 재연결해 마스킹된 증거73개를 받았다. 네트워크 설정은 바꾸지 않았다.

## 미실행·다음

**NOT_RUN:** 실제 목표 초기화, 토크ON/OFF, live, 재학습, 모델 변경, 패키지 설치·기존 환경 변경, push. G5/G6나 실기 성공으로 기록하지 않는다.

다음 현장 작업은 FIELD_GUIDE.md의 초기화 시험이다. 그 성공 결과를 검토한 뒤 기존 재무장 검사와 dry-run을 다시 확인하고 짧은 첫 동작 시험으로 넘어간다. 원격에서 현장 확인 입력을 대신하거나 모터 쓰기를 자동 실행하지 않는다.
