# 현장 목표 초기화 시험 안내

현재는 **현장 실행 전**이다. 초기화 코드의 모의 테스트와 기본 계획 출력만 수행했다. 실제 목표 쓰기·토크 변경·live는 NOT_RUN이다.

## 먼저 읽을 것

- 현재 목표 레지스터가0이므로 토크를 바로 켜지 않는다. VLA의 행동 cap은 토크를 켤 때 이미 남아 있는 목표에 의한 움직임을 제한하지 않는다.
- 목표 쓰기 자체가 토크를 켜는지 이번 현장에서는 미확인이다. 사람 입회·안정된 팔 지지·즉시 전원 차단 수단이 필수다. 움직이는 관절부에 손을 두지 않는다.
- 이 도구는 현재 위치를 원시값으로 읽고, 그 값과 정확히 같은 Goal_Position 패킷1개만 허용한다. 모드·보정·토크 레지스터 쓰기는 차단한다.
- 토크가 예상과 다르거나 통신·위치·온도·포트 해제 검사가 실패하면 재시도하지 않는다. `FIELD_STOP.json`을 남기고 새 live 진입을 차단한다. 이 파일과 원래 중단 기록을 삭제·이름 변경하지 않는다.

## 지금 실행해도 되는 명령

다음은 계획 출력만 한다. 장치·모델·모터 접근 없음.

```bash
bash ~/v6_process_1793887709179/operator_candidate/run_goal_initialization.sh
```

예상 출력: `PLAN_ONLY`. 이 출력은 실제 초기화 성공을 뜻하지 않는다.

## 현장 입회 후 운영자가 직접 실행할 시험 — NOT_RUN

LeLab과 미리보기의 follower 점유를 끝내고, 팔을 home 부근에 안정되게 받친 뒤 수행한다. Astra 브리지는 유지한다. `sudo -v`는 읽기 전용 fuser 점유 조회용 인증이며 시스템을 바꾸지 않는다.

```bash
sudo -v
bash ~/v6_process_1793887709179/operator_candidate/run_goal_initialization.sh --execute --operator-present --supported --stop-ready --out "$HOME/goal_init_field_$(date +%Y%m%d_%H%M%S)"
```

현장 조건을 실제로 확인했을 때만 터미널에서 `INITIALIZE_GOAL`을 직접 입력한다. 자동 입력은 거부한다. 이 명령은 실제 모터 레지스터를 쓰므로 무인 상태에서 실행하지 않는다.

- **성공 기준:** `GOAL_INITIALIZED_TORQUE_OFF`, 목표/현재 원시값 일치, 토크6개0, Goal 패킷1, 토크 패킷0, 정리 오류0, 포트 해제 확인.
- **중단 기준:** HOLD, 일부ON, 온도45°C 이상, 위치 변화, 불일치, 통신 오류, 점유·정리 오류. 팔 지지를 유지한다. 예기치 않은 움직임이면 즉시 전원을 차단한다. 다시 실행하거나 중단 기록을 지우지 말고 `RESULT.json`과 오류를 확인한다.
- 성공해도 토크ON·live를 자동으로 이어서 실행하지 않는다. 결과를 보고 기존 재무장 검사와 새 dry-run을 확인한 다음 첫 동작 시험으로 넘어간다.

## 종료 시 주의

종료·예외 시 새 목표나 토크OFF를 자동 전송하지 않는다. 마지막 목표와 토크가 남을 수 있다. 소프트웨어 종료가 즉시 물리 정지를 보장하지 않는다. 전원 차단이나 토크 해제 시 팔이 처질 수 있으므로 현장에서 지지한다.

## 보존·복귀

원본 모델·데이터·설치 환경·이전 실행기는 바꾸지 않는다. 새 실행기는 별도 `operator_candidate/`에 있다. 새 도구 사용을 중단하면 코드 복귀가 가능하다. 실제 모터 쓰기를 했다면 파일 복귀만으로 모터 상태가 원복되는 것은 아니다. 기존 v4 live로 되돌려 실행하지 않는다.
