# 현장 읽기 전용 진단 — 초기화 재시도 아님

모터 전원 OFF 상태에서 코드·모의 테스트·기본 계획 출력까지만 개발자가 검증했다. 실제 장치 실행은 운영자가 한다. 기존 FIELD_STOP은 삭제하거나 변경하지 않는다. 이번 진단은 해당 중단 기록의 해시가 일치해야 시작하며, live·초기화·재무장을 허용하지 않는다.

## 운영자에게 드릴 첫 명령

모터 전원은 아직 OFF로 두고 Jetson에서 다음 한 줄을 실행한다. 점유·서비스 검사가 통과하면 프로그램이 전원ON 및 READ_ONLY 확인을 안내한다. 팔이 안정된 지지대에 있고 즉시 전원을 끌 수 있을 때만 안내를 따른다. 프로그램은 전원을 직접 켜거나 토크/목표를 쓰지 않는다.

```bash
sudo -v && bash ~/v6_process_1793887709179/operator_candidate/run_torque_readonly.sh --execute --operator-present --supported --stop-ready
```

오류가 나오거나 검사가 거부되면 다음 명령 없이 그 출력을 확인한다. 프로그램의 안내 전에는 모터 전원을 켜지 않는다. READ_ONLY 확인 전에는 SDK와 장치를 열지 않는다. 운영자의 확인을 개발자가 대신 입력하지 않는다.

## 검사 내용

- LeLab inactive, follower serial 비점유, 알려진 보정 파일·FIELD_STOP 해시 일치.
- 목표/토크 쓰기가 허용되지 않은 송신 보호를 먼저 설치한다. 토크와 온도 레지스터의 READ만 허용한다.
- bus.connect(handshake=False), 독점 점유 확인, 관절별 동기 READ(한 번에 ID1개).
- 각 응답의 길이·ID·체크섬·오류 상태와 원시 바이트 보존. 토크가0이 아니거나 온도45°C 이상이면 즉시 추가 읽기 중단. 두 번 반복의 최대24회 READ이며 재시도0.
- 종료 시 bus.disconnect(disable_torque=False). 종료를 위해 토크를 켜거나 끄거나 목표를 쓰지 않는다.
- 결과는 `readonly_diagnostics/<고유값>/RESULT.json`과 `responses.jsonl`에 새로 생성한다. 원래 중단 기록은 계속 보존한다.

## 결과 해석

| 출력 | 알 수 있는 것 | 확정할 수 없는 것 |
|---|---|---|
| RESPONSE_REJECTED + 길이/ID/체크섬/통신 오류 | 이번 읽기에서 통신 응답 문제가 관측됨 | 모터 자체 고장 여부, 과거 사건의 직접 원인 |
| 오류 상태가 있는 정상 프레임 | 모터가 오류 상태를 보고함 | 기계 고장으로 단정할 수 없음; 상태 비트 검토 필요 |
| NONZERO_TORQUE_REPLY | 정상 형식의 0이 아닌 토크 응답이 관측됨; 즉시 정지 | 모터 자체 고장 또는 펌웨어 원인이라고 단정할 수 없음 |
| NO_MISMATCH_WITHOUT_WRITES | 쓰기 없이 관측한 두 차례에는 불일치가 없었음 | Goal 쓰기 후 문제 해결, live 허가, 실기 성공 |

동일 ID·동일 길이의 지연 응답은 프로토콜만으로 완전히 구분할 수 없다. 이 진단으로 관측되지 않은 현상을 정상이라고 단정하지 않는다.

## 개발자가 실제 한 것

관련 모의 테스트 로컬 기존64개+신규11개 통과. Jetson에서도 실행기60개+프로세스15개=75개 통과(exit 0), 셸 문법·기본 파일 검사 통과(exit 0). 처음 SSH 시간 초과가 있었지만 이후 연결되어 새 파일만 배포했다. `diagnosis_validation/`에 영수증·테스트 로그를 보존한다. FIELD_STOP은 해시 동일을 재확인했다. 실제 SDK 장치 연결·카메라·모터 읽기/쓰기·추론·학습·live는 NOT_RUN이다.
