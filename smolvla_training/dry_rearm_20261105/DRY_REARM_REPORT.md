## 확인한 중단 사유

중단 보존본은 `~/nov_live_prep_20261104/SERIAL_STOP.cleared_20261105_185629.json`이다. 사유는 `토크ON 관측; 이후 serial 작업 중단`, 관측은 `shoulder_pan: Torque_Enable=1`이었다. 무인 프로파일의 '하나라도 ON이면 중단' 조건이 작동했다. 이것은 토크가 켜진 근본 원인이 해결됐다는 뜻이 아니다. 파일 이름을 누가 변경했는지도 미확인이다.

SHA256 `16bf71d5f09ebb246a573a22cbad1faae57e5f50c0ae6ed945f2443c94797f5c`은 모든 실행 뒤 동일했다. 삭제·내용 변경·이름 변경을 하지 않았다. 기존 v4와 원래 공통 카메라 설정도 그대로다.

## 재개 절차의 범위

모터 재무장과 분리한 **1회 읽기/추론 재개 확인서**를 구현했다. 사용자에게 추가 승인 입력을 요구하는 절차가 아니라, 허용된 읽기 전용 실행 범위를 기록하고 검사하는 내부 절차다. 암호학적 사용자 인증이나 시스템 샌드박스라고 주장하지 않는다.

1. LeLab inactive·포트 비점유 확인 후 새 진단을 한다. 토크6개OFF, 위치모드0, 온도45°C 미만, 보정 일치, 팔5축 home±5°가 필요하다. ON/고온/오류를 읽으면 추가 serial 작업도 중단한다.
2. 60초 이내 진단에 대해 모델·보정·전후처리·정규화·home·카메라 설정 해시와 과거 중단 사유를 확인한다. 검토한 중단 파일 하나 이외의 새 중단 기록/해시 변경이면 거부한다.
3. 확인서는 5분 유효, 1회 사용이다. 실행 시작 시 별도 소비 기록을 추가하며 원래 중단 파일은 건드리지 않는다. 만료·변경·재사용은 거부한다.
4. 범위는 `READ_ONLY_DRY_RUN`, `live_permitted=false`, `motor_writes_allowed=false`다. `--live`는 모델/장치 import 전 거부한다. 실제 SDK 패킷 보호도 Goal/토크/모드/보정 쓰기를 차단한다.
5. 실행 중에도 기록·설정과 토크/온도/부하/Status를 검사한다. 최종 결과와 쓰기 횟수를 남기고 포트를 닫는다. 오류·종료 시 새 Goal_Position을 쓰지 않는다.

원래 v6의 중단 기록 거부 동작은 보존했다. 이번에는 별도 `so101_first_action_test_safe_v6_dry.py`에서 명시적으로 위 조건을 검증한다. **live 허가 또는 토크 활성화 확인서가 아니다.**

## 카메라 경로 문제와 해결

- 같은 RealSense D435가 연결돼 있었다(USB `8086:0b07`, serial `236223023645`). 현재 by-id의 index0은 `/dev/video2` 깊이영상 `Z16 `이고, RGB는 `/dev/video6`, USB 인터페이스03, `YUYV`다. by-id 이름만 보고 깊이 영상을 넣지 않았다.
- QUERY/ENUM ioctl만 사용해 형식을 확인하고 즉시 닫았다. 제어값·노출·네트워크·서비스 설정은 바꾸지 않았다.
- 기존 설정을 덮어쓰지 않고 실행 폴더의 `resolved_camera_config.json`에 파생 설정을 만들었다. RGB 경로는 `/dev/v4l/by-path/platform-3610000.usb-usb-0:1.1.2:1.3-video-index0`다. 해당 경로의 vendor/product/serial/interface를 실행 전 다시 검사한다. 다른 기기로 자동 대체하지 않는다.
- 데이터 키 `end_effector / ceiling_vertical / ceiling_oblique`는 유지했다. 저장된 전처리가 camera1/2/3으로 이름을 한 번만 바꾼다. 640×480 RGB,30fps,예열3초 유지. 실제 시작 이미지3장이 저장됐으며 직접 열어 빈/깨진 영상이 아님을 확인했다. Astra의 알려진 색 불일치는 유지했다. 학습 구도와 완전히 같다고 검증한 것은 아니다.

## AMP·추론 시간

체크포인트 `config.json`의 `use_amp=true`가 기존 독립 실행기에 반영되지 않았다. 설치된 LeRobot `scripts/lerobot_eval.py:775`는 `cfg.policy.use_amp`에 따라 `torch.autocast(device_type=device.type)`를 사용한다. 이를 읽기 전용 경로에 적용했다. 가중치 파일을 FP16으로 변환/저장하거나 BF16을 임의 선택하지 않았다.

최종 실행은 예열과 실제 추론을 같은 GPU 스레드에서 수행했다. 합성 예열 출력은 폐기하고 정책 reset 뒤 실제 관측을 사용했다. 합성 예열은 포트가 열리기 전에 실행했다.

| 최종 측정 | 초 |
|---|---:|
| 같은 스레드 합성 예열1/2 | 2.069923 / 1.339780 |
| 실제 관측 준비 | 0.008217 |
| 실제 관측 GPU 작업 | **1.752864** |

추론 전 전체5초 예산은4.9908초 남아 있었다. 마지막 실패는 전체5초 부족이 아니라 chunk 추론 제한이었다. 예열/스레드 통합만으로 해결되지 않았다. 실제 관측과 감시를 함께 돌릴 때 추가 지연의 세부 원인은 미확인이다. 감시/CPU 작업과 추론의 결합을 다음 소프트웨어 작업에서 계측해야 한다. 시간 상한·감시를 줄여 통과시키지 않았다.

최종 감시24회, READ 요청800패킷, Goal/레지스터 쓰기0, 차단 패킷0. 종료 시 대기 정책 스레드0, 정리 오류0. 정상 chunk로 채택된 개수0이므로 **새 첫 action 차이·전체 action 범위 검증은 완료하지 못했다.** 과거 v4 결과를 이번 통과 근거로 쓰지 않는다. 오프라인/모의 테스트가 실기 성공률은 아니다.
