# 개선 가능 범위 — 2026-11-08

## 확인한 문제

중단 직전 연속 두 모델 목표의 팔꿈치 값은86.870453도와83.651176도로3.219276도 차이다. 학습30fps 기준 명목 변화 속도는96.578293도/초다. 실행기는 목표 변화 속도20도/초와 현재 위치 대비2도 제한을 적용했다. 이 구간의 원래 궤적은 그대로 실행되지 않았다. 실제 팔꿈치는96.043956도로 남아 다음 모델 목표와12.392780도 차이가 났고10도 검사에서 중단됐다.

따라서 오류 이름인 큰 목표 점프는 연속 모델 예측 사이12.39도 점프가 있었다는 뜻이 아니다. 현행 검사는 원래 정책 목표와 현재 관절/직전 전송 요청을 비교한다. 현재 대비 추종 오차와 연속 정책 궤적의 불연속을 구분해 보고해야 한다.

## 모의 재현

기존 target_gate와 동일한 제한을 사용해96도에서80도로0.1도씩 변하는 합성 목표를 입력했다. 이상적으로 목표를 따라오는 가상 관절은161개 명령을 완료했다. 관절이 움직이지 않는 가상 관절은101개 명령 후 큰 목표 점프로 HOLD됐다. 두 경우의 예상 결과 단언을 통과했다. 실물에 데드밴드가 있다는 증거로 해석하지 않는다.

실행: python -B compare_tracking_models.py, 종료코드0. TRACKING_MODEL_COMPARISON.json에 결과를 저장했다. 실제 로봇·카메라·serial·추론·학습은 실행하지 않았다.

## 소프트웨어 개선 방향과 한계

1. 구현·배포 완료: 요청값, SDK 반환값, 실제 전송 직전 패킷의 정수 목표를 구분하는 계측. 모터의 수신/도달 증명은 별도이며 새 실기 기록은 아직 없다.
2. 다음 설계 대상: 원래 행동을 매번 잘라 다음 인덱스로 넘기는 처리와, 속도 제한에 맞게 궤적을 시간 방향으로 늘리는 처리를 구분한다. 뒤처진 관절 상태에서 다음 예측이 더 앞서가는 현상을 확인하고 추종 실패를 별도로 표시한다. 이 실행 알고리즘은 아직 수정·배포하지 않았다.
3. 현장 검증 필요: 작은 목표에 대한 실제 관절 추종과 SDK 추가 제한. 마찰·서보 설정·출력 여유 문제는 아직 미확인이다. 이를 확인하기 전에는 소프트웨어 변경만으로 약통 작업 성공을 보장할 수 없다.

기존 실행 제한과 HOLD는 유지했다. 이번 추가 작업은 저장 로그와 가상 모델 분석뿐이다. 재개 명령, 모터 설정 변경, 추가 live, 재학습과 push는 NOT_RUN이다.
