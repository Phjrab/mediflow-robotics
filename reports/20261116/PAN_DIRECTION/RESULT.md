# 손목 화면 오른쪽 미세 보정 — 2026-11-16

**현재 시험 자세에서 shoulder_pan 양수(틱 증가)가 손목 화면 기준 오른쪽이다. 기본 보정은 +6틱, +0.5274725°로 적용했다.** 실기에서는 +6틱 명령에 실제 +4틱(+0.3516484°) 움직였으며, 약통 뚜껑 마커 평면에 투영한 화면 중앙 조준점이 오른쪽 약1.51mm 이동했다. 이는 이번 자세의 국소 측정이다. 모든 자세에서의3D TCP 이동량이나 실제 집기 성공을 보증하지 않는다.

## 현장 확인과 실기

운영자가 VLA·텔레옵 정지, 현장 대기, 팔 지지를 확인했다. 실제 읽기에서6축 토크OFF/모드0/상태0/온도32~35°C/전압12.2V였다. 운영자가 팔을 받쳐 그리퍼를 약통A 위1~2cm에 놓았다.

현재 위치를 목표로 먼저 설정했다. 이 장비에서는 이 Goal_Position 패킷1회 뒤6축 토크가 이미ON으로 읽혀 별도 Torque_Enable 쓰기가 없었다. 자동 홈 이동·정책 실행 없이1초간 위치 변화0틱을 확인했다. 이후 운영자가 지지하는 힘을 줄여 자세가 유지됨과 손을 경로 밖으로 뺌을 확인한 뒤 미세 시험을 실행했다. 손을 뗀 후 어깨/팔꿈치에 일부 하중 잔차가 생겼으며, 시험 기준은 손을 뗀 뒤 안정된 새 표본이다.

| 구간 | pan 목표 | pan 실제(마지막0.8초 평균) | 약통 마커 중심(x,y) |
|---|---:|---:|---|
| 기준 | 2186틱 | 2186틱 | (353.5,188.875)px |
| +6틱 | 2192틱 | 2190틱 | (346.5,187.750)px |
| 원래 목표 복구 | 2186틱 | 2190틱 | (347.625,187.875)px |

약통은 고정, 손목 카메라는 팔과 함께 움직인다. 따라서 **마커가 왼쪽7px 이동했다는 것은 그리퍼/카메라가 약통에 대해 오른쪽으로 이동했다는 뜻**이다. 다른5축의 안정 구간 실제 틱은1308/2581/2543/1790/1070으로 같았다. 이5축에는 시험 목표를 쓰지 않았다.

운영자는 처음3mm라고 답했으나, 검은 정사각형 전체 한 변이 **3cm=30mm**임을 다시 확인했다. 마커ID9의4모서리 호모그래피를 사용해 화면(320,240)의 조준점을 마커 평면으로 옮기고, 기준 영상의 오른쪽 방향 성분을 비교했다. 이동량은0.0502578×30=1.507734mm다. 흰 테두리는 크기에서 제외했다. 화면 좌우 반전은없다.

작은 명령에는 이력 효과가 있다. 목표를2186틱으로 돌려도 실제가 즉시 돌아오지 않았으며, 후속 읽기에서는2189틱으로 남았다. 따라서 +6틱을 언제나 정확히 +6틱 실제 이동으로 해석하거나, 1.51mm/6을 임의 크기에 선형 확장하지 않는다. 해당 현상은 작은 명령에서의 데드밴드/정상상태 잔차와 일치하지만 P/I/D나 데드존 레지스터를 수정하지 않았다. **원래 목표 복구와 실제 원위치 복귀를 구별한다.**

실제 송신: 현재 위치 Goal_Position6축 패킷1회 + shoulder_pan Goal_Position단독 패킷2회. Torque_Enable레지스터 쓰기0, 그리퍼 한계 쓰기0, 보정/PID/가속도 쓰기0. 실제 미세 시험에서는 온도최고41°C(그리퍼 원본), 상태오류없음, 포트닫힘·비점유. VLA live는 실행하지 않았다.

## 소프트웨어 반영

- 공통 설정 `live/config.yaml`: 보정ON, +6틱에 해당하는+0.5274725°, 최대±1.5° 유지. 어깨 회전 고정 오프셋 방식 하나만 적용하며 어깨 서보 잔차 보상은 추가하지 않았다.
- 적용 구간: 기존 학습 집기 관절 범위와 명목 높이115.7~147.9mm, 앞으로1초 이내 닫힘 예측,0.2초 램프/닫힘 뒤0.5초까지. 다른 구간에는0°다.
- `live/assets/pan_camera_calibration_20261116.json`: 사용자30mm확인, 원본 시험 경로, +6명령/+4실제, −7px, 평면1.51mm, 복귀 잔차와 한계를 보존하고 해시를 검사한다.
- 검증 게이트는 실제 영상의 방향과 마커 평면 이동량을 요구한다. `scale_verified=true`지만 `geometry_verified=false`, `tcp_physically_calibrated=false`를 명시했다. 카메라 평면 측정을 전체 TCP 보정 완료로 가장하지 않는다. 명목 FK 높이는 추가적인 자세 선택 조건이다.
- Windows 기본 Python에NumPy가 없어 드러난 의존성은 표준 라이브러리 기반 동일 URDF 높이 계산으로 해결했다. 기존 FK 기준 자세의132.7359064mm와 일치 검사를 추가했다. Jetson venv/패키지 변경없음.
- 짧은 모의 실행에서 초기 파일/해시/FK 로딩이0.4초 제어 예산을 소모하던 문제도 수정했다. 제어 타이머는 초기화 뒤 시작한다.2초 초기화 지연을 넣어도0.2초 정책 루프가 실행됨을 검증했다. 정지 요청·온도·상태·통신 제한을 제거하지 않았다.

dry에서 집기 구간의 실제 보정 전송은0회였다. 고정된 현재 카메라와 가짜 홈 상태의 dry를 실제 집기 품질 검증으로 해석하지 않는다. 실제 구간의 보정 경로는 별도의 동일루프 모의와 이전 로그 산식 재생으로 확인했다. 재생 미래 목표는 당시 대기열의 대리 입력이며 실제 재실행 결과가 아니다.

Windows에서 초기에NumPy누락/샌드박스의 로컬HTTP소켓 제한/짧은 제어기간 초기화 문제가 드러났다. 초기 실패 로그는 보존했고 필요한 수정/로컬검사 권한으로 재검증했다. 검사 실패를 삭제하거나 보호 조건을 줄여서 통과시키지 않았다.

## 상태·파일

현재는 운영자가 맞춘 집기 직전 자세, 토크ON 유지다. 홈 자세로 이동하지 않았고 자동 live도 실행하지 않았다. 최종 실제 읽기와 웹/해시는 `final_read.json`, `post_checks.json`을 따른다. serial은 작업 끝마다 해제했다. LeLab/홈/관제/정렬/Astra 서비스는 유지/복원했다. 이전 실기·중단 기록은 보존했다.

변경/추가: `live/config.yaml`, `config_runtime.py`, `grasp_offset.py`, `stream_live.py`, `nominal_height.py`, 실측JSON, `tools/pan_camera_probe.py`, 두 모의 파일, `analysis/replay_pan_correction.py`. 이전 파일은 `.bak_20261116_1930` 및 stream의`.bak_20261116_1938`에 보존했다. 새 파일은 덮어쓴 원본이 없다. 상태 문서도별도백업했다. `commits.json`, `source_hashes.json`에 Windows/Jetson 로컬 커밋과 배포 일치를 기록한다. push없음.

현장에서 추가 크기 측정은 필요 없다. 보정 후 실제 집기 성공/다른 자세에서의 정밀 이동량은 다음 감독 실기에서 확인해야 한다. 홈 복귀 경로를 검토하지 않은 채 현재 자세에서 새 VLA를 자동 시작하지 않았다.
