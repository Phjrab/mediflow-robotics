# 제조사 SDK 온도 원인 분리

2026-11-11. **제조사 C++ SDK에서도 토크 OFF 상태의 온도 급변을 재현했다.** Python SDK·LeRobot·모델·실제 움직임은 발생의 필수 조건이 아니다. 센서/모터 펌웨어/전원/물리 통신 경로 중 정확한 고장 지점과 수리는 아직 미확인이다. 55°C 중단은 유지했다.

## 실행 도구와 쓰기 차단

제조사 Wiki가 연결하는 [공식 Linux SDK](https://github.com/ftservo/FTServo_Linux)의 commit `06fd3356dbd7bccd886b5a70d7ae0fccc6c76d38`을 별도 폴더로 받아 사용했다. 출처·압축 지문은 `SOURCE_RECEIPT.json`에 있다. 공식 SCS.cpp/SMS_STS.cpp 파서는 수정하지 않았다. 이 검사는 Windows FD 실행이 아니라 **공식 C++ 파서와 검토한 읽기 전용 전송 어댑터** 검사다.

`vendor_temperature_readonly.cpp`는 전송 직전에 ID1–6의 opcode2 READ40/63,폭1,정확한 길이·합 검사만 허용한다. 토크·위치·보정·리셋 패킷은 버스에 보내기 전에 거부한다. 수신은 ID·길이·상태·합 검사·원문을 보존하며 큐에 잔여가 있으면 버리지 않고 중단한다. 포트는 배타 소유하고 실패 시 추가 요청 없이 닫는다. 호스트 UART 설정은 모터 baud 레지스터 쓰기와 구별한다.

공식 SCSerial::end는 fd=-1 뒤 close를 호출하는 코드여서 실제 descriptor는 우리 어댑터에서 직접 닫는다. 시간 제한/인터럽트 안전성과 원문 기록을 위해 transport를 감쌌으므로 제조사 GUI 전체를 그대로 실행했다고 쓰지 않는다. FD의 숨은 쓰기 부재는 공개 문서만으로 입증하지 못해 장치 연결 실행을 하지 않았다. 자세한 검토는 `VENDOR_TOOL_REVIEW.md`다.

## 실제 측정

모든 아래 검사는 같은 제어보드·기존 6축 연결,무동작·토크 OFF였다. 각 검사에 55°C 중단이 있었고 결과는 모두55 미만이었다. 첫값을 포함하므로 표본 수는 루프 횟수보다1개 많을 수 있다.

|---|---:|---:|---:|---|
| 그리퍼만30Hz,초기6축확인 |20초|601|34 /35°C|34→35→34|
| 6축 각각30Hz |10초|301|36 /49°C|36→49→35|

대표 원문:36=`ffff06030024d2`,52=`ffff06030034c2`;37=`ffff06030025d1`,53=`ffff06030035c1`. 제조사 파서와 별도 수신 검증 모두 그대로 디코드했다. 다섯 정상 완료 검사에서 **11,440개 READ 요청/응답**을 노트북에서 재검사해 opcode·주소·폭·ID·상태·합 검사 일치를 확인했다. 전체 원문은 `jetson_results/vendor/`에 보존했다.

이는 몸체가 실제로16°C씩 수 ms에 가열·냉각된 것으로 설명하기 어려운 계측 이상이다. 하지만 정상 합 검사만으로 센서/ADC·모터 펌웨어·전원·선로의 어느 곳인지 확정할 수 없다. ID6만 읽어도 재현되므로 다중 ID 응답 혼합은 필수 조건이 아니다.

빠른 검사에서는 표본 수도 많았다. 단순히 “빠를 때 최고값이 높다”를 속도 원인 확정으로 쓰지 않는다. 중앙값보다8°C 높은 그리퍼 응답 수는 차례로0/601,1/301,1/601,2/1801,4/3601이었다. 이는 **저장 로그 분석용 분류**이며 runtime 온도를 필터링하거나 낮추는 처리가 아니다. 짧은 정상 구간이나 읽기 빈도 저하를 수리로 판정하지 않는다.

## 첫 무응답의 구분

첫 C++ 시도는 ID1 READ40 한 번에 응답이 없어 즉시 닫았다. 샘플0이며 온도도 읽지 못했다. 그 출력의 peak_c=0은 초기값으로,실제0°C 측정이 아니다. 사용자에게 DC가 켜져 있음을 확인받았고,이후 기존 pySerial의 같은 요청은 `ffff01030000fb`(토크OFF)로 응답했다. 뒤이은 제조사 검사는 정상 통신했다. 첫 무응답 원인을 DC 꺼짐 또는 특정 DTR/RTS 문제로 단정하지 않는다. 연결 초기 조건 차이 또는 일시 통신 문제는 미확인이다.

## 다음 물리 비교: 아직 실행하지 않음

같은 제어보드·같은 DC 전원을 유지하며 그리퍼 ID6을 기존 모터 체인 대신 보드에 직접 연결해 비교한다. 이때도 같은 ID6-only180/360Hz 조건을 쓸 수 있어 단순 요청량 감소와 경로 변경을 구분한다. 그리퍼 전용으로40/63만 읽는 경로를 `~/vendor_temp_isolation_20261111/vendor_temperature_isolation_ready`에 컴파일·모의 검증해 두었다. 케이블 이동·전원 재연결·직결 읽기는 아직 NOT_RUN이다.

첫 현장 단계는 팔을 안정적으로 받친 뒤 **팔로워 모터용 DC 전원만 분리**하는 것이다. 배선을 옮기기 전에 전원을 끄는 단계이며 Jetson 전원·USB·카메라는 유지한다. OFF 확인 전3핀을 옮기지 않는다. 다음 단계에서 옮길3핀선 한 가닥과 연결 지점을 안내한다. 부족한 선을 억지로 당기거나 단자 방향을 바꿔 끼우지 않는다.
