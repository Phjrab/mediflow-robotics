## 원인과 확인 한계

최고 온도는 28/29/29/31/30/34°C, 온도 HOLD는 0회다. 이번 건을 과열로 해석하지 않는다.

## 변경

- ID가 다른 패킷은 값으로 사용하지 않는다. 깨진 SYNC_READ 배치의 남은 응답을 폐기하고 입력 버퍼 reset+유한 drain 뒤 누락 축의 같은 주소·폭을 개별 재요청한다.
- 정상 SYNC_READ의 축별 응답 사이에는 버퍼를 비우지 않는다. 새 읽기 요청 직전과 오류 재시도 경계에서만 비운다.
- 기존 주기 내 최대3회 재시도, 동일 축·요청5연속 실패/200ms 무응답 HOLD를 유지한다. 버퍼 정리가 그 제한을 연장하지 않는다.
- HOLD 위치 유지도 입력 버퍼를 정리한 뒤 기존 최대5회 확인 절차를 사용한다. 정상 응답/목표/안정 검증 전에는 HOLD_CONFIRMED로 표시하지 않는다.
- 축별 ID 불일치, -6/-7, 입력 초기화/폐기 바이트를 summary.communication에 기록한다.
- 집기 기록의 JPEG 인코딩·파일 저장을 spawn 별도 프로세스로 분리한다. 주 프로세스는 제한된 공유 메모리에 RGB 복사와 비차단 큐 전달만 한다. 복사·큐 지연, 자식 CPU/인코딩/저장 시간, 손실·정리 결과를 계측한다.
- 기록기 생성도 READY 타이머 재설정 앞으로 이동했다. 홈 기준, 그리퍼48.5점, 오른쪽+6틱, speed0.33, READY 뒤180초 및 안전 설정은 그대로다. config SHA-256 `0cb647eeea9e85399b4f9094130699eb40a1e3a17113fe117a45069cf810f5cf`.
- 관제 미리보기의 기존 JPEG 스레드는 별개로 남는다. 프로세스를 분리해도 SoC CPU/메모리 경쟁은 존재하므로 모터 영향0을 보증하지 않는다.

## 실버스 비교 준비와 미완료 항목

`tools/recorder_bus_readonly.py`는 동일 저장 RGB3장으로 링버퍼 OFF/ON 각60초를 비교한다. 포트 점유와 토크OFF를 확인하며 READ만 허용하는 하위 패킷 가드가 모든 레지스터 쓰기를 막는다. 토크가 ON이면 임의로 끄지 않고 중단한다. CPU/요청지연/ID불일치를 기록하며 카메라 획득이나 모델 추론 부하는 포함하지 않는다.

Jetson SSH 추가 인증은 자동 승인 검토가 거부했다. 입력하려던 값이 사용자가 제공한 비밀번호라는 근거가 없다는 이유이며, 그 뒤 인증 우회나 추측을 시도하지 않았다. 따라서 Jetson 배포, 실제 버스60초×2, 수정본 실제 모델 dry-run 및 원본 로그 추가 수집은 NOT_RUN이다. 이전 dry 결과를 수정본 검증으로 재사용하지 않는다.

실버스와 수정본 Jetson dry-run 완료 전에는 새 live 준비 완료로 표시하지 않는다. 배포·검증 이후 실행 인자 계약은 `bash ~/so101_vla/live/run.sh --live --speed 0.33 --duration 180`이며 지금 Jetson에 이 수정본이 있다고 가정하고 실행하면 안 된다.
