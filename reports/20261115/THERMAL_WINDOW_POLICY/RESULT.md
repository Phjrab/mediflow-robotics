# 2초 온도 판정·학습 기준 팔꿈치 상한 — 2026-11-15

사용자 승인 범위에서 수정·Jetson 배포와 검증을 완료했다. **새 live는 실행하지 않았다.** 실제 모터 작업은 읽기뿐이며 보정·P/I/D·가속도·목표·토크·그리퍼 토크 한계 쓰기는 모두 0회였다. 기존 보정·모델·학습 원본과 중단 기록은 변경하지 않았다.

코드 커밋: Windows `466a8d8`, Jetson `dd770b6` (push 안 함). 배포한 17개 소스의 SHA256이 일치한다. 기존 파일과 설치된 홈 HTML은 `.bak_날짜시간`으로 보존했다. 실행기 백업은 `20261115_172325`, 설치 홈 HTML 백업은 `20261115_173855`다.

## 온도 보호

- 보호 입력은 `Present_Temperature` 주소63·길이1의 **새 개별 READ**다. sync-read bulk 온도나 기존 진단 필터가 이 값을 대신하지 않는다.
- 각 축 READ 요청 간격을 최소20ms로 유지한다. 매 표본에 요청·응답 시각, 이전 요청과의 간격, 송신/수신 원문, 응답 ID, 체크섬 검증 결과를 기록한다.
- 읽은 모든 표본이 55°C 이상인 연속 구간이 2초에 도달하면 HOLD한다. 정상값이 나오면 그 연속 구간을 끝내고, HOLD에 이르지 않은 고온 구간은 튐으로 기록한다.
- 유효한 2초 창의 중앙값이 50°C 이상이면 경고하고 55°C 이상이면 HOLD한다. 창 전체가 확보되기 전에는 중앙값 HOLD를 판정하지 않는다. 150ms 넘는 표본 공백은 연속 구간과 창을 다시 시작하게 하며, 통신/응답 오류의 기존 중단은 계속 적용한다.
- 이번 승인으로 이전의 “고온 재읽기 한 번이라도 높으면 즉시 HOLD” 및 “70°C 재확인 즉시 HOLD” 분기를 새 2초 규칙으로 대체했다. 단발/2회 연속81°C도 정상으로 복귀하면 계속하는 모의를 확인했다.
- 상태 오류·응답 ID/길이/체크섬 오류·USB/통신 오류·Ctrl+C·가동범위 보호는 유지했다. 시작 냉각 대기 중에도 온도는20ms 간격으로 확인하고 안내 출력만10초 간격으로 유지한다.

원본 온도는 숨기거나 정상 온도로 바꾸지 않는다. 실행 로그의 `temperature_protection`에 중앙값·연속 고온 시간·판정 근거를 남긴다. 튐 순간에는 추가 READ로 토크를 확인해 전압·부하·전류·상태·원본 패킷과 `thermal_spike_context`에 저장한다. 전압/부하/전류는 같은 bulk 표본에서, 토크는 바로 뒤의 별도 READ에서 얻으므로 각각의 관측 시각도 남긴다.

검증한20ms는 새 시리얼 READ 요청 간격이다. 모터 내부 ADC의 갱신 속도를 측정했다는 뜻은 아니다. 온도 응답 이상을 만드는 부품·전원 원인을 해결했다고 판단하지 않는다.

## 팔꿈치 상한 근거

학습 당시 회차 매핑으로 원본6개 parquet를 재구성했다. **빨강48·초록45·파랑44 =137회, 63,551행**이며 당시 기록된 마지막행 조정2곳도 적용했다. 회차 매핑 SHA256 `d6b2c82317ff8a1652f5dd6d3eb14e43899421257d19a3bf78caa0450927821a`와 원본 parquet6개 해시가 이전 학습 분석 기록과 모두 일치한다.

| 항목 | 최대값 |
|---|---:|
| 학습 action 팔꿈치 | 97.582420° |
| 위 action을 팔로워 SDK 정수 목표로 환산 | 3093틱 |
| 학습 observation.state 팔꿈치 | 97.098890°, 원래 위치 추정3088틱 |
| 보정 파일·모터 상한 | 3087틱 |
| 요청한 내부 여유 | 3틱 |
| **명령 상한** | **min(3093, 3087−3) =3084틱** |

action 최대값은 원본 `a_to_blue_20261102_212958`, 원본 episode14, merged episode71, frame364에 있다. 현재 팔로워 보정의 중심1983.5틱과 degree 모드를 사용해 `degree×4095/360+1983.5`를 SDK처럼 정수 변환했다. 관측 위치는 float32 양자화 때문에 가장 가까운 틱도 별도로 기록했다. 어느 쪽 최대값을 참고해도 최종 상한은3084틱이다. 자세한 증거는 `training_elbow_bound.json`에 있다.

유효한 명령 상한은 `live/config.yaml`의 `limits.elbow_flex=[880,3084]` 한 곳이다. 실행기·모의 버스·사이트가 이를 읽는다. 사이트 `/config`에서 같은 값을 반환하고 설치된 `/home-joints.html`은HTTP200임을 확인했다. 사이트를 새로고침하면 새 표기와2초 중앙값 표가 나타나며, 이후 설정은2초마다 갱신한다. 보정 파일과 모터의 Min/Max 레지스터는 쓰지 않았다.

## 과거 온도 원문 집계

보존된 실기 `steps.jsonl` 및 읽기 전용 `readings.jsonl`을 전체 경로에서 찾고 파일 SHA256으로 중복을 제거했다. DRY/mock/sim은 제외했다. 대상은 **16개 고유 로그, 축마다10,568개 표본**이다. 별도 형식의 기록이나 원문이 남지 않은 과거 실행까지 완전하게 복원했다고 주장하지 않는다.

| 축 | 55°C 이상 원시 표본 | 급변 의심 표본 | 원본 최고 |
|---|---:|---:|---:|
| 어깨 회전 | 0 | 0 | 37°C |
| 어깨 들기 | 3 | 10 | 81°C |
| 팔꿈치 | 0 | 1 | 42°C |
| 손목 굽힘 | 1 | 7 | 84°C |

**어깨 들기만의 현상이 아니다.** 급변 의심은 직전 대비+10°C 초과 또는1초 내+5°C 초과 등 원문 기반 분류이며 실제 과열/센서 오류 확정이 아니다. 표본 수와 이벤트 수는 다르다. 원본별 목록과 전압·부하·전류·토크 출처는 `history_counts.json`, `suspect_samples.csv`에 있다. 과거 토크가 기록되지 않은 곳은 `NOT_RECORDED`, 시작 때만 읽은 곳은 `startup_readback`으로 구분했다. 추정값을 당시의 새 토크 읽기로 표시하지 않았다.
