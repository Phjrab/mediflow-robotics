# 팔로워 USB 복구 후 실제 READ 검사

2026-11-15. 운영자는 원래3핀 배선 복원과 두DC ON을 확인했다. 실제 검사 결과는 **HOLD: 첫 모터 응답 시간 초과**다. 새2분 완료·정상 판정·home 확인·live는 수행하지 못했다. 오류 뒤 실제 serial 재시도는 하지 않았다.

## 포트 계약

| 역할 | by-id의 시리얼 | OS 장치 | 확인 |
|---|---|---|---|
| 팔로워 | `5AE6058306` | `/dev/ttyACM1` | udev 식별 일치 |
| 리더 | `5AE6085272` | `/dev/ttyACM0` | 팔로워로 사용 금지 |

`live/config.yaml`은 이미 원래 팔로워 by-id에 고정돼 있었다. `config_runtime.py`의 리더 제외 검사와 READ 도구의 정확한 경로 제한을 확인했다. `/dev/ttyACM1` 번호 자체에 고정하거나 리더 포트로 대체하지 않았다. config 값 변경은 필요 없었다.

## 실제 실행과 결과

- 실행 전 LeLab 텔레옵·녹화·추론 상태 모두false. root fuser로 팔로워 비점유 확인.
- Jetson PSmisc23.4에서 `fuser -- /dev/ttyACM1`가 사용법 오류를 냈다. 고정 절대 경로에 대해 `fuser /dev/ttyACM1`로 수정했다. 점유/조회 실패 거부 조건은 유지했고 관련 모의3개를 추가했다.
- Windows/Jetson 대상 모의29개 PASS 뒤 실제120초 READ를1회 요청했다.
- 시작 후 약0.263초, READ 요청1개에서 응답0바이트로 중단. 첫 요청은 코드의 고정 순서상ID1 shoulder_pan의 Torque_Enable(주소40,1바이트) 조회다. 읽기 전용 명령이며 토크 쓰기가 아니다.
- 완료 주기0, 온도·전압 표본0. 따라서 축별 튐 횟수·전압·home·토크OFF 확인은 **미확인**이다. 표본이 없어 튐0회라고 보고하지 않는다.
- 오류: `READ 통신 timeout; 재시도 없음`, 통신 코드-6. 응답 자체가 없어 체크섬 통과 여부도 판단할 수 없다.
- 실제 모터 레지스터 쓰기0, 포트 닫힘true, 정리 오류0. 종료 후root fuser exit1·출력/오류 없음으로 비점유 확인.
- 최근8분 커널 로그의 USB/ttyACM/CH343 관련 새 기록0. 이 결과로 모든 전기적·하드웨어 문제를 배제하지 않는다.

통신 초기화와 READ 패킷을 기존 정상 작동했던 제조사 기반 도구의 소스와 비교했다.1Mbps·8N1과 요청 ID/주소/체크섬에 원인이 될 차이를 찾지 못했다. 이것은 새 도구의 모든 실제 동작을 검증했다는 의미가 아니다. 전원·보드→첫 모터 신호 경로·보드 동작 상태의 정확한 원인은 미확인이다. USB 복구만으로 모터 통신 복구를 확정할 수 없다.

후속 소프트웨어 보강으로, 앞으로 발생하는 READ 실패 기록에는 요청ID·주소·폭·송신 원문도 포함하도록 했다. 기존 오류 파일은 덮어쓰지 않았다. 이 변경은 모의 검사로 검증했으며 실제 재조회는 하지 않았다.
