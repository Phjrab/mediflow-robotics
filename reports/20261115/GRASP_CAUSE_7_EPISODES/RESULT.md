## 2. 공식 LeRobot 대조와 입력 계약

설치된 LeRobot0.6.0의 `prepare_observation_for_inference`와 실행기 `pack_observation`을 저장 processor에 각각 통과시켰다. **3,050프레임 모두 전처리 텐서 차이0**, 50액션 후처리 차이0. 에피소드별 시작/닫힘/끝에서 공식 경로로 별도 재추론한 결과도 차이0이다. 모든 프레임에서 동일한 텐서의 비싼 모델 추론은 공유했고, 전체를 두 번 별도로 추론했다고 보고하지 않는다.

평가의 batch2와 실제 batch1 사이 수치 민감도는 대표 프레임 최대0.181°/점이었다. batch4는0.400으로 더 커 채택하지 않았다. 실제 실행은 batch1을 유지한다. 따라서 ①입력 처리 버그를 뒷받침하는 차이는 찾지 못했다. 녹화 action과 모델 오차가 있다는 사실만으로 입력 버그라고 판단하지 않는다.

자세한 대조표: `INPUT_TABLE.md`. 프롬프트는 `Put medicine bottle A into the blue basket`로 데이터셋과 글자 단위 동일하다. camera1/2/3은 end_effector/ceiling_vertical/ceiling_oblique이며 RGB640×480, float32 BCHW/255를 사용한다. 저장 모델 내부에서512×512 padding resize와[-1,1] 변환을 한다. state는5축 degree·그리퍼0~100이며 저장 체크포인트 MEAN_STD 통계를 사용한다. chunk50/n_action_steps50, 디노이징10, VLM16, use_amp=true가 학습 설정과 동일하다. RTC는 비활성이다. 임의 fp16 전환·디노이징 축소·입력 색상 보정·정규화 재계산은 하지 않았다.

## 4. 운영자용 녹화 action 재생

대상은 blue 통합93, 원본 `Supermassive111/a_to_blue_20261103_193835`의 episode1(사용자 회차2),438프레임이다. 참조 영상은 `recorded_blue_reference.jpg`. **모델 없이** 녹화action 타임라인을0.33배로 재생하며 약44.14초다. RGB와 관절값을 관제에 기록하고 완료 뒤 현재 위치를 유지한다. 물체 위치를 보며 경로를 수정하는 기능은 없으므로 녹화와 같은 배치가 필요하다.

허용 패킷은 READ와6축 Goal_Position sync-write뿐이다. Torque_Enable·보정·PID·가속도·토크 한계 쓰기는 모두 차단한다. 따라서6축 토크ON과 위치 모드가 필요하며 자동 토크ON을 하지 않는다. LeLab 텔레옵은 직접 정지한 뒤 실행한다. 활성 텔레옵을 종료하면서 간접적으로 토크를 끄는 경로도 피하도록 사전 점유 확인을 분리했다.

기존 가동범위 클리핑·온도·상태·통신·Ctrl+C 위치 유지 보호를 유지했다. 팔꿈치 상한은 공통 config의3084틱이다. 녹화 최댓값97.407° 등은 기존 범위로 잘리므로 모든 값이 완전히 무수정 전송되는 시험은 아니다. 모의 전체 재생에서는 팔꿈치537회/손목 굽힘75회 클리핑이 기록됐다. 집기 후보 팔꿈치-13.80°·손목82.81°는 한계 안쪽이다.

녹화에는 큰 프레임 간 변화가 있다. 0.33배에서도 인접 기록 기반 최대 평균 속도는 어깨 들기110.5°/s·팔꿈치114.9°/s이며 cubic 보간 순간 최대는그1.5배까지다. 0.33배는 재생 시간 비율이며 저속 상한을 뜻하지 않는다. 요청한 녹화 경로를 임의 수정하지 않고 수치를 공개한다. 큰 경로 전체를 비운 상태에서 운영자가 감독한다.

```bash
bash ~/so101_vla/tools/run_recorded_blue.sh --execute --operator-present
```

실행 결과는 `~/so101_vla/runs/REPLAY_BLUE_날짜_시간/summary.json`에 저장된다. 출력의 RUN_COMPLETE는 궤적 완료이며 집기 성공은 사람이 영상/실물로 판정해야 한다. 재생이 물리적으로 잘 되면 영상/정책 조건 쪽 증거가 강해지고, 명령은 도달했는데 실제가 못 따라가면③추종을 추가 검토한다. speed1.0 시험이나 chunk 변경은 이번 결과 없이 자동 적용하지 않았다.
