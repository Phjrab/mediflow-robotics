# SO-101 손목 카메라 VLM 데이터 촬영 도구

카메라 3대의 640×480 영상을 PC 브라우저에서 보고, 라벨과 함께 사진 또는 동작별 MP4 영상을 저장하는 Jetson용 도구입니다. 카메라 중계 서버(8010)와 겹치지 않도록 촬영 UI의 기본 포트는 `8020`입니다.

이 프로그램은 카메라만 읽습니다. 모터·토크·Leader/Follower·USB 리셋·캘리브레이션·텔레오퍼레이션·VLA/ACT 추론 API나 장치에는 접근하지 않습니다. 영상 녹화는 카메라 프레임을 파일로 저장할 뿐 로봇을 움직이지 않습니다.

## 설치

Jetson에서 이 폴더로 이동한 뒤 가상환경을 만듭니다.

```bash
cd so101_vlm_capture
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

Ubuntu/Jetson의 OpenCV 빌드가 필요하면 `opencv-python-headless` 대신 배포판의 `python3-opencv`를 사용할 수 있습니다. 카메라 권한이 없다면 현재 사용자를 `video` 그룹에 추가한 뒤 다시 로그인해야 할 수 있습니다. USB 포트를 재설정하지 마세요.

## 실행 전 읽기 전용 안전 점검

LeLab 화면에서 텔레오퍼레이션·녹화·추론 작업이 실행 중인지 먼저 확인합니다. 실행 중이면 그 작업을 중단하지 말고 촬영을 미룹니다. 다음 스크립트는 장치/점유/포맷과 실제 한 프레임 읽기만 확인하며 프로세스를 종료하지 않습니다.

```bash
source .venv/bin/activate
bash scripts/check_jetson.sh /dev/video6
```

`fuser` 출력에 프로세스가 있거나 `카메라를 열 수 없습니다`가 나오면 해당 PID를 강제 종료하지 마세요. `ps -fp PID`로 이름만 확인하고 기존 작업 담당자에게 점유 상태를 보고합니다.

```bash
fuser -v /dev/video2
ps -fp PID
```

## 실행과 접속

```bash
source .venv/bin/activate
python app.py --host 0.0.0.0 --port 8020
```

같은 네트워크의 PC 브라우저에서 `http://127.0.0.1:8020/`에 접속합니다. UI의 상태가 `카메라 연결됨`, 해상도가 `640×480`인지 확인합니다. 방화벽을 사용하는 환경에서는 관리자 정책에 따라 TCP 8020 허용이 필요할 수 있습니다.

## 권장 영상 촬영 절차

1. 약 종류, 자세, 권장 파지 부위 등 위쪽 라벨을 먼저 선택합니다.
2. `영상 녹화 시작`을 누릅니다. 시작 순간은 접근 전 프레임으로 자동 표시됩니다.
3. 로봇을 별도 시스템에서 조작하면서 `접촉 순간 표시`, `파지 완료 표시`를 누릅니다. 이 촬영 도구 자체는 로봇 명령을 보내지 않습니다.
4. 최종 결과를 성공/실패/사람 개입/미기록 중에서 선택합니다.
5. `녹화 종료 및 저장`을 누릅니다. MP4 한 개와 접근 전/접촉/파지 완료 핵심 프레임 3장이 저장됩니다.

표시 버튼을 빼먹으면 영상의 15%, 50%, 80% 지점에서 해당 프레임을 자동 보완합니다. 다만 정확한 순간에 표시 버튼을 누른 데이터가 더 좋습니다. 기본 녹화는 10 FPS, 최대 30초이며 실행 옵션 `--video-fps`, `--video-max-seconds`로 바꿀 수 있습니다.

한 영상은 한 번의 집기 동작만 담으세요. 거의 같은 동작을 연속 반복하기보다 약통 위치·회전·거리·조명·배경·접근 방향을 바꾸는 것이 중요합니다.

### 저장 영상 확인과 잘못된 영상 삭제

촬영 페이지 아래쪽의 `저장된 동작 영상`에서 MP4를 바로 재생할 수 있습니다. 각 영상에는 약통·자세·파지 라벨과 접근 전/접촉 순간/파지 완료 시각, 그 시각에서 추출한 핵심 프레임 3장이 함께 표시됩니다.

접촉 또는 파지 완료 표시 시각을 잘못 누른 영상은 해당 카드의 `영상 삭제`를 누르세요. 확인창을 통과한 정확한 trial 한 건만 활성 학습 목록에서 빠지며, 연결된 핵심 프레임 3장도 함께 빠집니다. 원본 MP4·프레임·JSON 기록은 즉시 완전 삭제하지 않고 아래 휴지통에 복사하므로 필요하면 수동으로 복구할 수 있습니다. 녹화 중에는 삭제할 수 없습니다.

```text
data/pilot/trash/trial_000001_YYYYMMDDTHHMMSSZ/
├── trial_000001.mp4
├── images/
├── trial.json
├── annotations.jsonl
└── deletion.json
```

## 기존 사진 촬영 절차

1. 로봇팔은 현재 자세 그대로 두고 약통만 손으로 배치합니다.
2. 화면에서 약통 종류, 상태, 가시성, 집기 가능성, 전략, 스킬, 지시, 목적지를 선택합니다.
3. 바구니 매핑이 확정되지 않은 초기 설정에서는 목적지를 직접 선택합니다. 확정 후 `config/medicine_baskets.json`의 `null`을 `basket_1` 또는 `basket_2`로 바꿀 수 있습니다. 이 설정은 안내용이며 선택을 강제로 덮어쓰지 않습니다.
4. `사진 한 장 저장`을 한 번 누릅니다. 클릭 한 번마다 정확히 한 장만 저장됩니다.
5. `데이터 현황`에서 개수와 JSONL/이미지 일치 여부를 확인합니다.

`다시 촬영`은 기존 자료를 삭제하지 않고 새 촬영을 안내합니다. `마지막 촬영 삭제`는 화면에 표시된 최신 이미지/라벨을 확인한 후에만 그 한 건을 삭제합니다. 최신 항목이 중간에 바뀌면 삭제를 거부합니다.

서버는 명백히 모순된 라벨을 HTTP 400으로 차단합니다. 브라우저 검증을 우회해도 저장되지 않습니다. 실제 좌표, 관절 각도, 모터 명령은 기록하지 않습니다.

## 저장 위치와 형식

데이터는 프로젝트 내부 `data/pilot/`에 저장되며 `data/` 전체가 `.gitignore`에 포함됩니다.

```text
data/pilot/
├── images/scene_000001.jpg
├── annotations.jsonl
├── videos/trial_000001.mp4
├── trials.jsonl
├── trash/                         # UI에서 뺀 영상의 복구용 원본
└── session.json
```

시작할 때 기존 이미지·영상·JSONL을 확인해 가장 큰 번호 다음 번호를 사용합니다. 기존 파일은 덮어쓰지 않습니다. `annotations.jsonl`에는 사진과 영상에서 추출한 핵심 프레임이 동일한 형식으로 들어갑니다. 영상 프레임에는 `trial_id`, 영상 경로, 영상 내 시간, 수동/자동 선택 여부가 추가됩니다. `trials.jsonl`에는 영상 단위 메타데이터와 세 핵심 프레임 목록이 들어갑니다.

## 종료와 데이터 검증

UI의 `촬영 종료`를 누르면 카메라를 해제하고 세션을 `closed`로 기록한 뒤 서버를 종료합니다. 터미널에서는 `Ctrl+C`도 같은 정리 절차를 수행합니다.

카메라 없이 저장·번호 연속성·덮어쓰기 방지·모순 차단·한 건 삭제·누락 탐지를 검증할 수 있습니다.

```bash
python -m pip install -r requirements-dev.txt
python -m pytest -q
```

수집 후 UI의 `데이터 현황`을 열어 `JSONL과 이미지·영상 경로가 일치합니다`를 확인합니다. 추가 확인이 필요하면 테스트를 다시 실행합니다. 원본 데이터나 로그는 Git에 추가하지 마세요.

## 학습용 컴퓨터로 안전하게 복사

먼저 촬영을 종료하고 학습용 컴퓨터에서 아래처럼 새 목적지 폴더로 복사합니다. `rsync`는 부분 전송을 이어갈 수 있고 기존 대상 파일을 임의로 삭제하지 않습니다.

```bash
rsync -av --progress jetson-user@127.0.0.1:/path/to/so101_vlm_capture/data/pilot/ ./so101_pilot_copy/
```

복사 전후 파일 목록/체크섬을 비교합니다.

```bash
find data/pilot -type f -print0 | sort -z | xargs -0 sha256sum > pilot.sha256
sha256sum -c pilot.sha256
```

`pilot.sha256`은 원본 폴더 기준 상대 경로가 유지되는 위치에서 검사하세요. 이미지, 토큰, 비밀번호, 원본 로그는 Git 커밋 대상이 아닙니다.

## 현재 환경에서 확인된 상태

실제 Jetson에서는 실행 전에 위의 읽기 전용 점검을 수행하고, 기존 카메라 중계·텔레오퍼레이션 작업과 장치 점유가 겹치지 않는지 확인해야 합니다. 촬영 UI는 8020, Astra/RealSense MJPEG 중계는 8010을 사용합니다.
