# 첫 동작 시험 전 준비 결과 — 2026-11-05

현재 판정은 **HOLD**다. 첫 동작 시험 및 토크 활성화는 실행하지 않았다.

## 실제 수행

- 기존 v6의 기준과 중단 기록을 보존한 채 반복 dry-run을 실행했다. 카메라 관측·관절 읽기·추론만 허용하고 모터 쓰기를 패킷 단계에서 차단했다.
- 저장된 후처리를 50개 행동에 한 번 적용하는 최적화를 재사용했다. 실제 체크포인트에서 기존 후처리와 최대 절대 차이 0이었다.
- CPU 후보는 해당 프로세스의 PyTorch/OpenCV 스레드 수만 6에서 1로 줄였다. 시스템·기존 환경·모델 파일은 수정하지 않았다. 같은 저장 입력·seed의 행동 최대 차이는 0이었다.
- 기존 `RobotController` 원본 3개를 수정 없이 로드하는 첫 시험 adapter, 명시적인 현장 입력, 종료 시 새 목표를 쓰지 않는 처리, 실제 Moving 읽기, LIVE 입력 대기 중 센서 감시를 추가했다.
- 신규 모의 테스트 20개 통과. 실제 모터·카메라·serial을 열지 않는 테스트다. 이 중 가짜 하드웨어의 가짜 목표 호출은 실기 쓰기가 아니다.

## 반복 측정

50개 행동 / 30Hz = **1.666667초**가 현재 지연 상한이다. 느린 결과는 폐기하고 HOLD한다.

| 조건 | 완료 / 계획 | 통과 | 측정 결과 |
|---|---:|---:|---|
| 기존 일괄 후처리, 독립 프로세스 재실행 | 2 / 3 | 0 | 1회 GPU worker 1.753669초 초과. 다음 회는 최종 감시 포함 1.673426초 초과. 세 번째는 실행하지 않음 |
| 프로세스 CPU 스레드 1개 후보 | 3 / 3 | 0 | GPU worker 1.693466 / 1.684747 / 1.690057초, 모두 HOLD |
| 카메라·serial 없는 저장 입력 비교 | 각 방식 5회 | 별도 실기 판정 없음 | 일괄 후처리 평균 1.326653초, 최대 1.332036초 |

앞서 단일 v6 dry-run의 1.593988초 통과가 있었지만 반복 안정성 통과를 뜻하지 않는다. 저장 입력 측정과 실시간 관측·감시 조건의 차이는 확인됐다. 카메라 처리, GIL 경쟁, GPU/메모리 경합 각각의 기여도는 **미확인**이다. 속도가 빨라졌다는 이유로 감시·시간 상한을 완화하지 않았다.

반복 실행은 전부 모터 쓰기 0, 포트 해제 확인, 기존 중단 기록 보존이었다. 각 원본 로그는 별도 실행 폴더에 남아 있다.

## 현재 상태 읽기 결과

기존 `RobotController.read_status()` → 새 읽기 adapter 경로로 확인했다. 카메라는 이 점검에서 열지 않았다.

| 항목 | 결과 |
|---|---|
| Torque_Enable | 6개 모두 0 |
| Operating_Mode | 6개 모두 0 |
| 온도 | 30~35°C |
| Present_Load / Status / Moving | 0 / 0 / false |
| 현재 위치 | [-3.208791, -97.362637, 96.571429, 43.472527, -4.615385, 7.160343] |
| 현재 원시 위치 | [2065, 847, 3082, 2575, 1812, 530] |
| 기존 Goal_Position 원시값 | **[0, 0, 0, 0, 0, 0]** |
| 기존 목표 = 현재 위치 | **불일치** |
| 재무장 | **거부** |

현재 자세가 home 부근이어도 기존 목표가 안전한 것은 아니다. 기존 목표는 몸체 관절의 보정 범위 밖이다. **토크를 켜거나, 팔을 원시 목표 0으로 맞추는 조작을 하지 않는다.** 목표를 현재 위치로 초기화하는 절차는 현장 지지 및 별도 검토가 필요하다. 이전 Goal 쓰기 뒤 토크ON 관측의 인과관계는 확정되지 않았으므로 자동 재시도·자동 보정은 추가하지 않았다.

## 코드와 검증 범위

- `first_trial.py`: 기본은 계획 출력, `--inspect`는 읽기만 수행한다. live는 반복 3/3 통과·현장 입회·팔 지지·정지 수단·직접 REARM/ENABLE/LIVE 입력을 요구한다. 현재 반복 결과로는 live가 차단된다.
- `trial_runtime.py`: 저장 전처리의 카메라 변환을 한 번만 적용한다. 카메라 RGB 640×480, 보정·단위·모델 해시를 확인한다. IO만 serial을 소유하고 정책에는 bus를 전달하지 않는다.
- `operator_arm.py` / `arm_source.py`: 현재 목표와 현재 원시 위치가 정확히 같은 경우에만 명시적 토크ON 패킷을 허용한다. 자동 목표 수정 없음. 실제 실행 **NOT_RUN**.
- `first_trial_core.py`: 온도, 부하, 상태, home, 관절 한계, 큰 점프, NaN/차원, 신선도, 시간 및 속도 조건을 검사한다. 첫 시험은 몸체 0.5°/step·20°/s 이하, 최대10스텝/5초다.
- `controller_source/`: 기존 controller 및 모델/오류 정의의 동일 사본. 원본 `robot.py`를 수정하지 않았다.

카메라 신선도는 호스트 수신 시각과 이미지 중복 후보 검사다. 센서 생성 시각 자체를 보장하지 않는다. 소프트웨어 감시는 GIL·SDK 정지에 독립적인 하드웨어 watchdog이 아니다. 첫 동작 경로는 모의 검증 단계이며 G5/G6 통과, 실기 안전 인증, 약통 투입 성공으로 기록하지 않는다.

## 종료 상태와 미실행

종료 점검에서 follower·손목·RealSense 포트 비점유, Astra 브리지 유지, 해당 웹 모니터·v6 dry-run 프로세스 0개를 확인했다. 마지막 관절 읽기에서 토크는 모두 OFF, 최고 온도35°C였다. 신규 코드의 물리 동작 경로는 실행하지 않았다.

**NOT_RUN:** 토크 활성화/해제, Goal_Position 쓰기, live, 재학습, 모델·원본 변경, push. 기존 토크ON 중단 기록은 삭제·이름 변경·내용 변경하지 않았다.

**다음 작업:** 지연 상한을 유지한 추가 최적화와, 원시 목표 0 상태에서의 안전한 목표 초기화 절차 검토. 현재는 사용자가 실행할 모터 명령이 없다. 성공할 때까지 반복하거나 검사 조건을 해제하지 않는다.

읽기 재개용 안전 명령은 `RUN_ORDER.md`에 있다.
