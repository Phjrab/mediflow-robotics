사용자가 승인한 온도 재읽기와 소프트웨어 목표 보상을 배포했다. 새 live는 실행하지 않았다. 실제 팔꿈치 설정은 READ 패킷 12회로만 확인했고, 나머지 검증은 모의 또는 실제 모델·카메라 + 가짜 모터 dry-run이다.

## 온도 보호의 변경

- bulk 또는 개별 읽기에서 55°C 이상을 발견하면 **같은 축**을 즉시 2회 개별 재읽기한다. 두 재읽기가 모두 55°C 미만이어야 `spike`로 기록하고 계속한다. 한 번이라도 55°C 이상이면 `confirmed`로 기록하고 기존 HOLD 경로로 들어간다.
- 첫 값과 바로 다음 재읽기가 둘 다 70°C 이상이면 두 번째 재읽기를 기다리지 않고 고온 확인을 끝내 HOLD한다.
- 재읽기의 ID·길이·체크섬·상태·통신 오류는 정상 온도로 취급하지 않는다. 검증 실패는 계속 중단하며 쓰기를 허용하지 않는다.
- 시작 중에도 확인된 55°C 고온은 중단한다. 50–54°C는 기존 냉각 대기를 유지한다.
- 원본 온도, 보호에 채택한 온도, 재읽기 결과를 구분해서 로그에 저장한다. 기존 시간 필터는 관찰용으로 남겨 두었다. 축별 `thermal_confirmation.counts`에 튐/고온 확인 횟수가 저장된다.

이 조치는 검증된 일시적 응답을 재확인하는 소프트웨어 변경이다. 센서·전원·배선 중 어떤 부품이 튐을 만드는지 해결됐다는 뜻은 아니다. 외부에서 만진 온도만으로 내부 과열을 배제하지 않는다.

## 소프트웨어 목표 보상

`live/tracking_compensation.py`를 추가했다. 현재는 **팔꿈치에만 활성화**했다. 다른 몸체 축은 `config.yaml`의 `tracking_compensation.enabled_axes`로 선택할 수 있고, 그리퍼에는 적용하지 않는다.

- 보정 범위에 클리핑·정수 변환된 원래 목표와 실제 위치 차이를 사용한다.
- 같은 방향의 오차가 0.3초 유지되고 목표 변화가 완만할 때 일부 오차를 누적한다. 누적·감쇠 변화율은 최대 0.75°/s이고, 오차 반전 시 누적을 멈추고 감쇠한다. 빠른 모델 동작을 느리게 제한하는 기능은 아니다.
- 보상 상한은 3°이며 SDK 정수 변환 여유 1틱을 남겨 내부 상한은 약 2.912°다. 가동범위 밖 보상은 누적하지 않는다. 팔꿈치 3082틱 상한과 나머지 기존 범위는 그대로다.
- 시작 토크 준비·홈 복귀·HOLD 위치 유지에는 이 보상을 적용하지 않는다. 원본 모델 목표, 보상 전 정수 목표, 보상량, 최종 정수 목표, 실제 위치를 함께 기록한다.
- 보정·P/I/D·가속도·토크 한계 레지스터는 변경하지 않았다. 읽기 도구는 검토한 ID3 READ 패킷 이외 전송을 차단한다.
