# 온도 진단 보강 — 2026-11-15

진단용 필터·원본 추적·공통 화면을 보강했다. Windows와 Jetson의 대상 모의 검사26개 통과. 실제 모터 읽기·쓰기·live는 실행하지 않았다. Jetson에는 리더 USB `5AE6085272`만 보이고 원래 팔로워 USB `5AE6058306`은 없다. 운영자가 마지막으로 확인한 두 DC 전원 상태는 OFF다. 따라서 요청한 새2분 실기 읽기와 그 결과에 따른 live 준비 완료는 NOT_RUN이다.

## 적용 범위

- `live/thermal_diagnostics.py`: +10°C 초과 단발 상승,1초 안 +5°C 초과 상승을 표시한다. 직전 표본은 원본값으로 비교하고,1초 창의 원본 최저값 대비 상승을 계산한다. 첫 표본은 낮추지 않는다. 제안된55°C 연속3회·0.3초 초과와 원본70°C 연속2회 조건은 **진단 비교용**으로만 계산한다.
- 실제 실행기의55°C 중단·상태 오류·통신 검증은 유지했다. 필터값을 `sample['temperatures']`에 덮어쓰지 않는다. 단발81°C를 무시한 채 실제 동작을 계속하도록 변경하지 않았다. 원인이 확정되지 않아 높은 값을 제외하면 진짜 과열도 가릴 수 있기 때문이다.
- `stream_live.py`, `thermal_read.py`: 매 관측에 원본 채택 온도·일괄 읽기 온도·전압·상태·전체 피드백 바이트·개별 온도 원시 응답·시각·오류 누적을 기록한다. `summary.json`의 `thermal_diagnostics`에 축별 튐 횟수·원본 최고·진단값 최고·오류 종류를 남긴다. 튐 횟수는 채택 원본 온도 시간열 기준이며 원본 최고는 일괄/개별의 유효 원문도 포함한다.
- 전압은 일괄 피드백의 온도와 같은 패킷이다. 뒤이어 읽는 개별 온도와는 별도 패킷이다. 이 차이를 `voltage_association`과 응답별 시각에 명시했다. 비동시 값을 동시 측정이라고 쓰지 않는다.
- `vla_monitor.py`, 홈·관제 화면: 같은 진단 객체의 값을 게시한다. 원본·진단값·전압을 구분하고 필터가 보호를 제어하지 않음을 표시한다. 홈 서버는 캐시 파일만 읽고 serial을 열지 않는다. 새 기록이 없거나1.5초 지나면 대기 표시다. LeLab 텔레옵이 온도를 방송하지 않는 동안 실시간 온도를 만든 것처럼 표시하지 않는다.
- `tools/servo_thermal_readonly.py`: 원래 팔로워 by-id만 사용하며 리더 포트로 대체하지 않는다. 실제 DC ON 확인 옵션이 없으면 장치를 열지 않는다. root fuser 비점유 확인·단독 포트 소유 후 명령2 READ만 전송한다. 토크·목표·보정·PID·가속도 쓰기 경로는 없다. 토크ON, 원본55°C, 상태 오류, 잘못된 응답, USB 끊김, Ctrl+C에서 종료·포트 해제한다. 입력 flush와 오류 후 재시도는 없다.

더 넓게 시도한 기존 `StreamingTests` 전체 검사는 첫 시도에서 운영자 정지/간헐 카메라 사례 실패와 Ctrl+C 모의의 시작 준비 중 KeyboardInterrupt로 완주하지 못했다. 운영자 정지 단독 재실행은 PASS다. 기존 전체 검사까지 전부 PASS했다고 보고하지 않는다. 이 작업에서 검사 조건이나 제어 제한을 약하게 바꿔 해당 결과를 숨기지 않았다.

홈8022·진단 API8767·관제 자바스크립트8766은 HTTP200과 새 필드/문구를 확인했다. API의 실제 응답은 새 온도 기록 대기이며 가짜 값을 화면에 게시하지 않았다. Python·자바스크립트 문법 검사 PASS.

## 과거 원문 재분석 — 새 실기 결과와 구분

`analysis/replay_temperature.py`로11/12의6개 저장 프로필(각20초)을 재분석했다. 제안된 진단용 +10/+5 규칙에서는 튐 의심15표본, 그때 **모터가 보고한** 전압12.2~12.3V였다. 기존 중앙값+8°C 분석과 규칙이 달라 횟수도 다르다. 이 결과를 새2분 연속 검사나 독립 전압계 측정으로 쓰지 않는다. 유효 체크섬이나 모터 자체 전압만으로 전원 문제와 센서/펌웨어 문제를 완전히 분리할 수는 없다.

## 실제 읽기 준비 경로

현재는 실행하지 않는다. 원래 팔로워 USB가 다시 보이고 실제 DC ON·토크OFF가 확인된 뒤에만 다음 진단을 실행한다. LeLab이 해당 포트를 점유하면 이 도구는 열지 않고 거부한다. 임의로 다른 프로세스를 죽이거나 토크를 변경하지 않는다.

```bash
sudo -v && PYTHONPATH="$HOME/so101_vla/live" ~/venvs/smolvla-py310/bin/python -B ~/so101_vla/tools/servo_thermal_readonly.py --execute --dc-on --duration 120 --out "$HOME/so101_vla/runs/thermal_readonly_$(date +%Y%m%d_%H%M%S)"
```

위 명령의 `--dc-on`은 물리 전원 확인을 대신하지 않는다. 새 실기 읽기가 NOT_RUN이고 팔로워 USB도 없으므로 이번 보고에서는 live 실행을 권하지 않는다.

## 보존·복귀
