# 복귀 후 할 일 — 2026-11-08 보완판

이번에 모터를 움직이는 새 명령은 만들지 않았다. 보간 실행 후보는 모의 전용으로 실제 연결을 차단한다. 기존300스텝 명령은 이미 사용됐고 HOLD 기록이 있으므로 재사용하지 않는다.

## 첫 단계: 설정 읽기만

1. 팔이 안정적으로 받쳐져 있고 주변에 걸림이 없는지 눈으로 확인한다. Jetson은 켠다. follower DC 전원을 연결한다. 토크를 수동으로 켜거나 live를 실행하지 않는다.
2. Jetson 터미널에서 아래 명령 하나를 실행한다. sudo 인증은 기존 포트 점유 조회에 쓰이며 설정을 바꾸는 명령은 없다.

```bash
sudo -v && bash ~/run_servo_readonly_20261108.sh --execute --operator-present
```

3. 질문이 나오면 READ_CONFIG 한 단어만 입력한다. 스크립트가 직접 읽는다. 초기 토크6개OFF, 위치모드0,45도 미만이어야 진행한다. 하나라도 토크ON이면 토크를 끄지 않고 즉시 중단한다. 이때 팔을 손으로 밀거나 이전 ENABLE 명령을 반복하지 않는다.
4. SERVO_CONFIG_READONLY_COMPLETE, motor_register_writes=0, port_closed=true이면 완료다. 출력된 결과 폴더를 Codex에 알려 주면 저장 JSON만 읽어 분석할 수 있다. HOLD나 통신 오류가 나오면 재시도하지 않고 그 출력을 남긴다. DC 전원이 없으면 응답이 없어 통신 오류로 중단될 수 있다.

## 읽는 것

실제로 설치된 SDK 제어표에 존재하는 항목만 조회한다. P/D/I 계수, 양방향 오차 무시 구간, 토크 한계, 가속도·목표 속도·전압·Phase 등이 대상이다. 펌웨어/모델 원시 바이트와 주소24·25·67은 공급사 문서에 근거한 별도 READ로 기록한다. 정의가 다른 SDK 주소71은 자동 조회하지 않는다. 숫자 의미나 단위를 임의로 추정하지 않는다.

작업 전후 토크와 온도를 다시 확인한다. 목표·토크·모드·보정·Lock·PID·설정 쓰기는 전부 금지된 가드가 적용된다. bus.connect(handshake=False), 개별 READ, bus.disconnect(disable_torque=False) 경로다. robot.connect/configure/calibrate는 호출하지 않는다. 카메라를 열거나 정책을 불러오지 않는다.

## 그다음 순서

설정과 SDK 최종 목표의 실제 계측을 대조해 작은 목표에서 움직임이 부족한 원인을 판단한다. 현재는 그 실측이 없어 원인이 확정되지 않았다. 이후에만 현장용 새 재무장 절차와 짧은 감독 시험을 준비한다. 보간 후보의 모의 통과는 실기 승인이나 약통 투입 성공을 뜻하지 않는다.

Ctrl+C는 읽기를 중단하고 포트를 닫는다. 토크 변경 명령은 보내지 않는다. 예상 밖 움직임이 있으면 DC 전원을 끄고 팔이 처지지 않게 지지한다.
