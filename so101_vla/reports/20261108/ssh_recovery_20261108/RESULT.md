## 완료

노트북의 이더넷 연결은 유지하고 저장된 일반 Wi-Fi 프로필에 추가 연결했다. Jetson은 기존 Wi-Fi를 그대로 사용했다. 인터넷 목적지는 이더넷, 기존 Jetson 목적지는 Wi-Fi 경로로 선택되는 것을 확인했다. 핫스팟은 사용하지 않았고 랜선을 옮길 필요도 없었다. 공유기·DNS·방화벽 설정은 변경하지 않았다. 접속 주소·계정·비밀번호는 기록하지 않았다.

처음 연결한 무선 프로필에서는 연결 후 드라이버 단절 및 자동 복구 이벤트가 발생했다. 드라이버 자체 원인은 미확인이다. 저장돼 있던 다른 무선 프로필로 전환한 뒤 실제 SSH 인증, 30초 연결 유지, 이후 여러 차례 파일 전송·명령 실행에 성공했다. 이 결과는 장시간 연결 안정성을 보장하지 않는다.

## 남은 사항

최신 저장 진단은 여전히 `1793945949525475776`이다. 당시 토크 6개 OFF, home 범위 통과, 주소42 목표 0과 현재 위치 불일치가 기록돼 있다. **현재 실시간 상태가 아닌 과거 저장 결과**다. 주소67 결과는 아직 없으며 기존 FIELD_STOP 검토도 남아 있다. 이번 네트워크 복구나 모의 테스트 통과로 이를 해제하지 않았다.

다음 안전한 소프트웨어 재개 명령(저장 파일만 읽음):

```bash
~/venvs/smolvla-py310/bin/python -B ~/v6_process_1793887709179/operator_candidate/review_saved_readiness.py
```

추가 실기 읽기는 현장 운영자가 DC 전원·팔 지지·즉시 정지 수단을 확인하고 직접 READ_ONLY를 입력할 때만 진행한다. 개발자가 이 입력을 대신하거나 live를 실행하지 않았다.

## NOT_RUN / 롤백

로봇·카메라·serial 접근, 레지스터 쓰기, 추론, 학습, 서비스 조작, 초기화·재무장·live, push는 NOT_RUN이다. 기존 중단 파일과 모든 원본 결과를 보존했다.

코드 롤백 시 위 백업의 기존 4개 파일만 복원한다. 신규 보조 파일은 실행하지 않은 채 남겨도 된다. FIELD_STOP·실기 결과·모델·데이터는 롤백 대상이 아니다. 네트워크 복구는 노트북의 일반 Wi-Fi 연결만 추가한 것이며 이더넷·공유기 설정은 바꾸지 않았다.
