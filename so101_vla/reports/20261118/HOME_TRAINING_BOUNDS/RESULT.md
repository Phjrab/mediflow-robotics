어깨 들기 850~856틱은 학습과 새 시작 범위에 모두 들어간다. 학습 범위 양쪽에 5틱을 더한 뒤 홈 ±23틱과 기존 실제 위치 안전 범위의 교집합을 쓴다. 팔꿈치 실제 상한 3087틱과 명령 상한 3084틱은 그대로다. 그리퍼 열림 설정은 직전 배포본의 49.612점에서 요청한 48.5점(정수 전송 1205틱)으로 맞췄다. 집기 오른쪽 보정은 +6틱이다.

공통 판정에서 0.5초를 충족하면 홈 이동 없이 시작한다. 이동이 필요하면 기존 저속 경로로 원래 홈 목표에 접근한다. 후속 시도는 같은 정수 목표만 재전송하며 3회 후에도 수렴하지 않으면 HOLD한다. 실행기와 관절값 사이트는 같은 홈 계산과 0.5초 판정 함수를 사용한다. 온도·통신·가동범위 보호를 유지했고 보정값·P/I/D·가속도에는 변경이 없다.

tmux 종료 뒤 호출한 터미널에 해당 실행의 종료 사유 한 줄과 실행 폴더를 표시한다. 실행 폴더가 생기기 전의 오류는 실패한 시작 단계 및 해당 실행의 시작 기록 폴더를 표시한다.

18:12·18:14 실행의 실제 시작 패킷을 복원해 각각 0.560초, 0.509초에 홈 통과를 확인했다. 동일 제어 루프의 가짜 서보에서 두 건 모두 홈 이동 패킷 없이 모의 정책 28스텝을 실행했다. 소프트웨어 검증 결과이며 실제 집기 여부는 다음 실기에서 확인한다.

Jetson 전체 모의 145개 통과. Windows 144개 통과, Linux 전용 1개 건너뜀. 850·856틱 통과, 866틱에서 고정 홈 목표 3회 후 HOLD, 보정이나 목표 확장 없음.

Jetson에서 실제 모델·3카메라와 가짜 서보를 사용한 dry-run 30.011초, 1,293스텝을 완료했다. 모의 어깨 858틱에서 0.533초 유지 후 홈 이동 없이 통과했다. 모터 쓰기·묶음 대기 0, 카메라 정리 오류 없음. 이 dry-run에서 집기 보정이 발동한 스텝은 없었고, +6틱 설정과 기존 보정 회귀 테스트를 확인했다.

관절값 API에서 850·856틱은 통과, 866틱은 거부했고 배포 HTML은 HTTP 200이었다. tmux 종료 모의에서 기존 HOLD 로그를 연결해 `HOLD home shoulder_lift 850/842`와 해당 runs 경로가 호출 터미널에 남는 것을 확인했다. 실제 live는 실행하지 않았다.
