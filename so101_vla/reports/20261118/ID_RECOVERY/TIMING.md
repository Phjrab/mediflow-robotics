# 1초 타이밍 계측

수정본은 매 루프 `loop_timing` JSONL에 시작 기준 주기(ms), 읽기·쓰기·카메라 접근·JPEG 공유메모리 복사/큐·관제 큐·추론 submit/result에서 막힌 시간(ms), 완료된 추론 총소요(ms), 마지막 전송 액션 인덱스와 선택 액션 인덱스를 기록한다. 중간 읽기 오류로 끝나는 루프도 finally에서 소요 시간을 남긴다. 절대 monotonic 시작/종료와 unix 시각도 함께 남겨 다른 기록과 연결한다. 실기 `serial_read`는 순수 UART 대기만이 아니라 `io.checked()` 내 파싱·안전 검사·동기 패킷 JSON 기록까지 포함한다.

READY부터1초 구간별로 summary.json의 `loop_timing.windows`와 종료 터미널에 다음을 표시한다.

- 루프별 시작 간격 역수의 평균/p5/최소 Hz. 첫 루프의 주기는 미측정이다.
- 해당 구간에 수집된 추론 1회 소요의 평균/최대 ms. 준비 전 첫 추론은 READY 정보에 따로 남고 구간 추론에 중복 포함하지 않는다.
- 전송된 액션 인덱스의 초당 증가량/(30×speed). 마지막 부분 구간은 실제 지속시간으로 나눈다. 구간 경계의 인덱스는 전송 표본 사이 선형 보간이다.
- p5<25Hz 또는 진행률<0.8이면 `루프 밀림`. 측정 작업 중 큰 항목과 액션 버퍼 비어 있음/비동기 추론 대기/카메라 대기 표시를 함께 남긴다.
- 비동기 추론 총소요와 별도 JPEG 자식 CPU는 제어 스레드 작업 시간에 더하지 않는다. CPU 스케줄링 인과관계를 입증한 지표는 아니다. 의도적인 cadence 대기도 작업 원인과 분리한다.

요약 구간은 루프 완료 시각 기준이다. 경계를 넘는 긴 호출의 비용은 완료 구간에 기록되며, 끝난 실기의 위치 유지 처리를 완료한 다음 요약을 출력한다.

읽기 전용60초 OFF/ON 비교도 같은 표를 만든다. 그 시험에는 모델과 목표 전송이 없으므로 추론/액션 진행률은 `NOT_APPLICABLE_NO_POLICY`이며0을 추종 실패로 오해하지 않는다.

## 19:35 과거 로그

현재 로컬에 보존된 검토 기준 55목표/1.62676초라는 전체 집계는 약33.81목표/초다. 이 값은 루프 주기 분포나 마지막1초 p5가 아니다. ID1 약170ms 지연은 확인됐지만, 해당 실행 원본 패킷·루프 전체가 이번 작업 중 새로 수집되지 않았으므로 마지막1초 Hz p5/최소, serial read/write 분해, 액션 진행률은 미확인이다. 과거 로그에 없던 CPU·JPEG 비용도 재구성하지 않았다.

이전 가짜 모터 dry46.806Hz, 18:46 실기44.565Hz는 실행 전체 집계이며, 새계측과 동일조건 A/B 결과로 취급하지 않는다. 새 실제 버스60초×2와 수정본 Jetson dry-run은 NOT_RUN이다.
