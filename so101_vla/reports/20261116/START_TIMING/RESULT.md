# 출발·묶음 재생 타이밍 수정 — 2026-11-16

**재현한 실행기 타이밍 오류를 수정했고 모의 검사와 실제 카메라·모델180초 dry-run을 통과했다.** 카메라는 이동하지 않았다. 실제 robot/serial에 접근하거나 모터 목표·토크·설정을 쓰지 않았다. 새 live는 운영자가 아래 명령으로 실행한다.

```bash
bash ~/so101_vla/live/run.sh --live --speed 0.33 --duration 180
```

이는 소프트웨어 구동 검증 통과 후의 실기 명령이다. 실제 약통 집기 성공과 물리적 추종 개선은 이번 dry-run에서 검증한 항목이 아니다.

## 1. 두 종류의 타이밍 차이를 분리했다

### 녹화 초반의 대기

three_color137회·63,551프레임을 다시 읽었다. 어깨 들기/팔꿈치의 action이 초기값에서2° 이상 변하는 상태가3표본 이어지는 첫 지점을 측정했다. 이 정의에서136회는 움직임을 검출했고1회는 미검출이다. 데이터에서 앞부분을 삭제하지 않았다.

| 색상 | 검출 회차 | 출발 중앙값 | p95 | 최대 |
|---|---:|---:|---:|---:|
| red | 48 | 2.43초 | 6.80초 | 9.00초 |
| green | 44 | 1.78초 | 3.61초 | 5.10초 |
| blue | 44 | 1.73초 | 5.01초 | 6.73초 |
| 전체 | 136 | 1.93초 | 5.82초 | 9.00초 |

비교 기준blue93번의 검출 시점은59프레임,1.97초다. 녹화 첫50프레임의 팔꿈치 변화폭은0.97°뿐이다. 초기 모델 목표가 더 일찍 움직이면 같은 시각의 첫50 MAE가 커질 수 있다.1.97초의 녹화 대기를0.33배로 그대로 재생하면 약5.96초가 된다.

다만 **초기 예측 차이가 모두 하나의 일정한 시간 오프셋 때문이라고 확인한 것은 아니다.** 다른5축으로 시간 이동을 맞추고 팔꿈치를 별도로 확인한 진단에서는3개seed 모두 최적 이동량0프레임이었다. 이전 홈 기준의 첫50 팔꿈치 MAE3.61°를 시간 이동으로2°로 맞췄다고 주장하지 않는다. 실행기에 임의 대기를 추가하거나 첫 액션을 잘라내거나 모델 가중치를 바꾸지 않았다. 이 진단은 `demonstration_timing.json`에 보존했다.

### 추론 중 재생이 멈췄을 때의 실행기 오류

기존 `chunk_alignment`는 추론 소요시간×재생Hz를 “이미 소비한 액션”으로 계산했다. 기존 버퍼를 다 써서 실제 타임라인이 멈췄어도 소비량을 계속 늘려, 새 묶음50개가 이미 만료됐다고 버리고 다시 추론하는 경우가 있었다.

수정 후에는 **실제로 소비한 타임라인의 첫 미전송 인덱스**를 기준으로 이어 붙인다. 벽시계 기준 추정량은 진단 로그에 별도로 남긴다. 정상 재생 중의 시간 진행과0.33배속은 그대로이며, 시작 시 첫 묶음은0번 액션부터 쓴다.

## 3. 실제 카메라·실제 모델 dry-run

기존 `entry.py --dry-run --duration 180 --speed .33` 경로를 실행하고, 로그 관찰 callback만 추가했다. 모터 버스는1차 지연을 흉내 낸 가짜 버스다. 프로세스 전체에서 실물serial open을 차단했다. LeLab을 종료하거나 텔레옵을 켜지 않았다. 카메라 정렬 미리보기만 잠시 해제하고 검사 후 복구했다.

| 항목 | 결과 |
|---|---|
| 판정 | PASS / RUN_COMPLETE / exit0 |
| 실행 구간 | 180.024초 |
| 가짜 목표 전송 | 8,595회 |
| 모델 추론 | 56묶음, 평균1.437초/최대1.487초 |
| 묶음 대기 | 최대0초/합계0초(초기 로딩 제외) |
| 실제 전송 루프 | 48.66Hz |
| 모델 타임라인 | 실측9.9006action/s, 설정30×0.33=9.9 |
| 첫 묶음 | 건너뜀0개, 첫model_phase0 |
| 버린 묶음 | 0개 |
| 카메라 실패 | 손목0/수직0/사선3, 사선은초기연결 |
| 최대 프레임 공백 | 0.057/0.049/0.058초 |
| 실제 모터 쓰기 | 0회 |
| 종료 | 카메라 정리 오류0, 미리보기 복구 |

온도·토크·추종 값은 dry-run의 가짜 버스 값이며 현재 실물 모터 측정값이 아니다. 카메라/모델/추론시간/루프시간은 실제 측정이다. 사진은 정렬한 원본 카메라 입력을 사용했다. 모델과 그리퍼 조임 완화·추종 보상의 실제 집기 효과를 이번 검사로 확정하지 않는다.

처음10개 목표는 `dry_summary.json`, 전체 관찰 로그는 `dry_trace.jsonl.gz`, 타이밍 검산은 `dry_timing_validation.json`에 저장했다. 원본JSONL은 Jetson에 그대로 남겼다. 원래 관제의 실기 상태 캐시도 보존·복원해 가짜 관절값을 현재 실물 값으로 남기지 않았다.
