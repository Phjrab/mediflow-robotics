### 11월 20일 · 어깨 들기·팔꿈치의 짧은 목표 반전 완화

15:30 성공 실행에서 관찰한 떨림을 줄이는 선택 옵션 `--smooth-reversals`를 Jetson에 반영했다. 로그 재생에서 약통 접근 중 두 축의 짧은 전송 목표 변동(95백분위)이 각각 23%, 27% 줄었다. 실물 감소율은 미확인이다. 실제 모델·3카메라·모의 팔 0.4배속 180초 검증과 모의 검사 255개 및 별도 검사 묶음이 통과했다. 모의 송신 48.68Hz, 묶음 대기 0초, 실물 쓰기 0회였다. 사선 카메라의 읽기 실패 3회가 기록됐고 실행은 완주했다. 기존 시연 명령에 선택 인자를 추가하면 PING·100회 읽기·영상 보존을 거쳐 완화 옵션을 시험한다.

### 11월 20일 14:40 · 실제 VLA 파란 바구니 투입 확인

### 11월 19일 팔 도착 전 닫힘 수정

21:03 실물 기록의 대표 닫힘에서 어깨 들기와 팔꿈치의 전송 목표−실측은 −54.59°와 +60.04°였다. 두 축 모두 움직이고 있었다. 청크 교체 직후에는 혼합 지연도 관측됐지만 실제 닫힘 시점의 큰 오차는 전송 이후에 남아 있었다.

현장 커밋 `0498532`를 Jetson에 배포했다. legacy와 raw는 닫기 요청 시 네 팔축의 원본 정책 목표−실측이 각각 ±3°에 들어올 때까지 그리퍼 열림을 유지하며, 1.5초에 도달하면 다음 제어 검사에서 닫힘을 허용한다. 온도 100°C 이상 패킷은 진단용으로 기록한다. 기존 온도 보호는 그대로 적용된다.

저장 로그 재생에서는 대표 닫힘이 0.578초 대기 후 허용됐다. 실제 모델·카메라 3대와 모의 모터로 수행한 legacy 0.5배속 dry-run은 60.019초, 2,908스텝, 묶음 대기 0초, 실제 모터 쓰기 0회였다. 닫힘 대기는 13회로 도착 해제 9회, 요청 철회 4회였다. 새 코드로 실물 파지 성공 여부는 아직 검증되지 않았다.

### 11월 19일 저녁 실물 0.5배속과 화면 정렬

운영자가 실행한 legacy 0.5배속은 180초 시간 만료로 종료했다. 목표 전송 7,965스텝, 완전한 1초 구간당 평균 44.25회, 묶음 대기 0초, 응답 ID 불일치·통신 코드 -6·-7은 모두 0회였다. 오른쪽 +6틱 보정 적용은 0회였다. 어깨 회전의 원시 온도 기록 최고 150°C, 별도 보호 재측정의 2초 창 중앙값 최고 30°C, 그리퍼 최고 49°C였다. 어깨의 원시값과 보호 계열 차이는 다음 시연 전 확인 대상이다.

닫힘 폭이 가장 큰 세 번째 시도에서 손목 영상 기준 약통 A는 손가락 사이 중점의 오른쪽에 있었다. 명령 시 약 119px, 실제 닫힘 시작 시 약 191px였다. 후자는 일부 가려진 표식으로 추정했다. 같은 기준에서 대표 학습 닫힘은 7px였다. 학습 137회 중 실제 닫힘을 식별한 135회와 비교해 어깨 회전·들기 피드백은 모두 5백분위 아래였다. 대표 실패는 좌우 빗나감으로 판정했으며 집기·투입 연속 성공은 확인되지 않았다.

관제 사이트에 학습 첫 프레임을 50% 겹쳐 현재 화면과 비교하는 모드를 배포했다. 천장은 고정판의 차이와 학습 평균 대비 약통 뚜껑·바구니 입구 좌표를, 손목은 보이는 두 병 끝점의 차이를 표시한다. 세 카메라의 새 프레임 수신과 브라우저 갱신·투명도를 검증했다. 이 분석과 관제 검증에서 모터 쓰기는 0회였다.

### 11월 19일 시연 전 통신 및 legacy 속도 확인

운영자가 12V 재연결 후 실행한 PING에서 ID 1~6 모두 정상 응답했다. 운영 실행기 `92ba835`와 같은 읽기 경로로 6축 100회 검사를 완료했고, 전 축에서 -6·-7·응답 ID 불일치가 각각 0회였다. 포트 종료를 확인했다. 원래 실행기에 버퍼 비우기와 같은 요청 재시도 처리가 들어 있다.

실제 모델·카메라와 모의 모터를 사용한 legacy 0.5배속 60초 dry-run에서 묶음 대기는 총 0초였고, 1초 창별 평균 제어 주파수는 37.60~49.52 Hz였다. 총괄이 Jetson 저장 로그를 대조했다. 시연 속도는 0.5, 예비 속도는 0.33이다. 이번 검사에서 모터 레지스터 쓰기는 0회였으며 180초 live와 실제 집기·투입은 미실행이다.

### 11월 19일 후속 결과 — 기본 10회 추론 유지

Jetson Orin에서 기존 SmolVLA와 원래 raw FIFO로 180초를 다시 실행했다. 입력은 저장한 RGB 3장, 관절은 실시간으로 갱신하는 모의 팔이다. 2,897개 액션을 순서대로 소비했고 제어 루프는 29.99 Hz, 고유 정책 처리율은 16.09 actions/s(30 Hz의 53.65%)였다. 실물 모터 쓰기와 카메라 개방은 0회였다. 누적 묶음 대기는 83.66초였고 24 actions/s 기준에 미달했다. 이전 15.82/s 시험은 실제 카메라를 사용해서 두 수치의 차이를 수정 효과로 판정할 수 없다.

기본 10회의 CUDA 단계 계측에서 이미지·상태·언어 입력 임베딩은 239 ms(그 안에 3뷰 비전 236 ms), 후속 추론에 쓰이는 VLM 캐시 생성은 110 ms, denoising 합계는 965 ms였다. RGB 복사를 줄인 후보는 같은 출력을 냈지만 전체 지연 p95가 1.431초에서 1.445초로 늘어 기각했다. 별도 실험에서 10·4·1회의 호출 p50은 각각 1.379·0.791·0.504초였다. 1회는 기본과 팔꿈치 목표가 최대 41.26° 달랐다. 운영 설정은 10회로 유지한다.

학습 원본 6그룹으로 137회·63,551행의 로컬 LeRobot v3 학습용 파생본을 구성했다. 공식 로더에서 모든 회차의 50액션 경계를 확인했고 12개 표본의 36개 뷰가 원본 픽셀과 일치했다. 독립 평가용 촬영 세션은 아직 없다. X-VLA의 6축 순서·후처리 검사는 CPU에서 통과했으며 실제 후보 체크포인트 학습·추론 및 물리 평가는 미실행이다.

## 코드의 범위와 제한

현재 v4는 SO101Follower를 직접 사용하며 RobotController 단일 경로를 거치지 않는다. 30Hz, 추가step cap0.5도(명목15도/초), 속도 상한20도/초, LeRobot max_relative_target2.0, 시작50도미만/운전55도미만, 부하/Status/수치/첫목표/home/프레임정지 검사가 있다. 그리퍼 제한은 각도가 아니라0~100 단위다.

이들은 작성된 소프트웨어 조건이며 실제 충돌 회피나 독립 정지버튼, 물리한계, 토크 활성화 무튐을 보증하지 않는다. 동기 추론 약3.08초는50step의 명목 소비1.67초보다 길다. 추론 중 마지막 목표를 유지하지만 비동기 감시/실시간성은 미검증이며5초 안에 일부step만 실행될 수 있다. 종료/예외/Ctrl+C 시 HOLD는 통신 상태에 따라 실패하거나 지연될 수 있다. 실제 live 성공률과 지정 바구니 투입은 측정하지 않았다.
