# 9주차 D — 실행 순서·종료 토크·텔레옵 수정

## 행동 순서 동기화

이전 몸통 목표에 실제 관절이 도달하기 전에는 다음 정책/보간 행동을 소비하지 않도록 해당 A 모델에만 추적 gate를 적용했다. 대기 중 기존 목표를 같은 명령 처리·제한 경로로 다시 보낸다. 파지 접촉 때문에 빈 집게 목표에 도달하지 않을 수 있어 그리퍼를 몸통 도달 판정에서 제외했다.

현재 판정은 팔꿈치4도/나머지 몸통3도에0.1도 측정 여유, 목표 대기2초다. 약21도 뒤처짐은 여전히 대기한다. 이 판정은 충돌 검출·파지 성공 검증이 아니며,0.1도 보정도 약4도 잔류 오차의 원인을 진단한 것은 아니다.

## 중단 뒤 팔 낙하

원위치 복귀만 막고 기존 disconnect의 토크 해제를 그대로 둔 누락을 확인했다. 이 경로는 사용자의 전원 상실 같은 낙하 설명과 일치한다. 추적 실패·명시적 정지·미완료 종료 시 새 관절값으로 유지 명령을 보내고 토크 해제 없이 연결을 닫도록 수정했다.

읽기/유지 명령 실패 시 추측한 복귀 동작을 보내지 않고 기존 목표·토크를 남기며 복구 경고를 기록한다. 이 경우 완전 정지는 보장하지 못한다. 종료 뒤 모터가 계속 켜져 있을 수 있고 발열 위험도 있어 감독·복구가 필요하다. 기계식 브레이크나 전원 상실 방지는 아니다.

## 텔레옵 시작 오프셋 원복

기존 상대 제어는 `팔로워 시작값 + 리더 변화량`이어서 리더만 원위치로 맞춰도 팔로워가 촬영 당시 자세로 돌아오지 않았다. 사용자가 이 현상을 지적했고 절대 자세 추종 복귀를 승인했다.

시작3초 동안 팔로워에서 리더 관절값으로 보간하고, 실제 자세 차이를 확인한 뒤 직접 추종으로 전환한다. 시작 때만 몸통 명령당5도·그리퍼2단위 제한, 이후 기존 직접 설정 사용.15초 안에 맞지 않으면 중단한다. 정렬 실패는 토크 유지 종료, 정상 추종 후 일반 텔레옵 종료는 기존 토크 해제 동작이다. 이는 전체 옛 코드를 되돌린 것이 아니라 추종 의미를 복구한 수정이다.

## 검증 상태

추론/종료 관련13개, 텔레옵 관련11개 로봇 없는 테스트를 PC와 Jetson에서 각각 통과했다. PC 통합24개 회귀도 통과했다. 원본 코드를 백업하고 모든 로봇 작업이 비활성일 때 배포·서비스 재시작했으며 서버 정상 상태를 확인했다. 새 종료 유지·절대 정렬의 실제 검증은 남아 있다. 배포 후 로봇 명령은 보내지 않았다.
