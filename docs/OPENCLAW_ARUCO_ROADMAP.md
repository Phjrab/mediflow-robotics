# OpenClaw + ArUco SO-ARM101 진행 기록

작성 시작: 2026-10-05 (KST)

## 목표

자연어 작업 명령을 안전한 결정론적 로봇 기능으로 연결한다.

```text
사용자 명령
  -> OpenClaw 작업 선택
  -> 검증된 로컬 API
  -> ArUco 기반 장면 좌표
  -> IK/안전 경로 계획
  -> LeRobot 모터 제어
```

OpenClaw 또는 LLM이 관절각을 직접 생성하거나 실시간 모터 루프에 참여하지 않는다.

## 고정 정의

- A: 가장 큰 약통 / 가장 큰 A 바구니
- B: 중간 약통 / 중간 B 바구니
- C: 가장 작은 약통 / 가장 작은 C 바구니
- 기존 카메라, calibration, ArUco, Depth, 데이터셋은 임의로 초기화하지 않는다.
- 포트 8000의 구형 LeLab과 포트 8022의 현재 LeLab을 동시에 실행하지 않는다.

## 안전 원칙

- 실제 동작은 별도 사용자 승인 전 금지한다.
- 1차 구현은 카메라 읽기, 마커 검출, 좌표 계산, IK 계산, 경로 출력만 허용한다.
- 쓰기 가능한 로봇 API는 기본 비활성화한다.
- 작업영역, 관절범위, 속도, 단계별 최대 이동량, 타임아웃, 단일 실행 잠금을 강제한다.
- 인식 신뢰도가 낮거나 필요한 마커가 없으면 동작하지 않고 실패한다.
- OpenClaw에는 허용 목록 방식의 고수준 함수만 제공한다.

## 진행 단계

### 0. 기존 자산 조사

- [x] Jetson에서 현재 사용 중인 ArUco 검출 코드와 실행 서비스를 찾았다.
  - 검출/웹 코드: `/home/USER/so101-medicine-bootstrap/models/yolo11n-medicine-smoke-v1/medicine_yolo_web.py`
  - 기준 설정: `/opt/so101-rgbd/astra_rgbd.example.json`
- [x] 마커 ID와 실제 의미를 확인했다.
  - 작업대 기준점: 0, 1, 2, 3
  - 바구니: A(큰 바구니)=6, B(중간)=5, C(작은)=4
- [x] 기존 카메라/좌표 설정을 조사했다.
  - 작업대 기준 좌표는 존재하지만 `T_B_W`는 `null`이다.
  - 로봇 작업범위와 높이도 아직 정의되지 않았다.
- [x] 기존 FK/URDF 자산을 찾았다.
  - URDF와 읽기 전용 FK는 있으나, 검증된 TCP/IK는 없다.
- [x] 읽기 전용 장면 스냅샷과 검출 결과를 보관했다.
  - raw 프레임에서 ID 0~6 모두 검출됨.
  - LeLab 가이드가 합성된 스냅샷은 검출 입력으로 사용하지 않는다.

### 1. 장면 상태 API

- [x] 2026-10-05에 세 카메라의 프레임 신선도를 읽기 전용으로 확인했다.
- [x] 저장된 raw 천장 프레임의 ArUco ID와 좌표를 JSON으로 반환한다.
- [x] A/B/C 의미 매핑을 설정 파일로 분리했다.
- [x] 필수 마커가 누락되거나 로봇 기능이 활성화된 설정이면 fail-closed 한다.
- [ ] 실시간 세 카메라 상태/타임스탬프를 하나의 읽기 전용 API로 묶는다.

2026-10-05 현재 Astra 원본 프레임 10장을 연속 검사했다. 일부 단일 프레임에서
기준 마커 3이 빠졌지만 2개 프레임에서는 ID 0~6이 모두 검출되었다. 현재 조명에서
뚜껑 3개를 안정적으로 검출하도록 기존 `param2=25` 검출이 실패할 때만
`param2=18`로 재검출하고, 고정된 C/B/A 열마다 가장 강한 원을 하나씩 선택하게 했다.
예전 프레임에서 바구니 테두리가 추가 원으로 잡히는 문제를 피하면서 현재 10/10
프레임에서 뚜껑 3개가 검출되는지 확인했다. 이는 원본 프레임에만 적용한다.

2026-10-05 사용자 확인 후 X 가이드는 픽업 기준에서 제외했다. 현재 장면에서는
실제 약통 뚜껑 원 3개를 검출하고, 고정 배치 순서 C/B/A로 신원을 대응한다.
이는 위치 검출이지 임의 배치에서의 약통 분류는 아니다.

### 2. 좌표 변환 검증

- [x] 픽셀 좌표를 ArUco 작업대 XY 좌표로 변환한다.
- [ ] 작업대 좌표를 로봇 베이스 좌표로 변환한다. (`T_B_W` 실측 필요)
- [ ] 알려진 작업대 점을 이용해 변환 오차를 측정한다.
- [x] 실제 약통 뚜껑 중심과 바구니 마커 중심 XY를 계산한다. X 표시는 사용하지 않는다.
- [x] 화면 오버레이와 JSON을 함께 생성해 사람이 검수할 수 있게 했다.

주의: 기준 마커 4개로 계산한 homography의 재투영 오차가 작다는 사실은
실제 자/로봇 기준 정밀도가 검증됐다는 뜻이 아니다. 독립된 실측 점 검증이 필요하다.

2026-10-05 동기화 RGB-D 30프레임 진단에서 depth/color 등록과 모든 마커 검출은
성공했지만, depth 기준점 간 거리는 설정값보다 15.1~49.8 mm 짧았고 작업대 좌표
rigid-fit RMS는 약 21.1 mm였다. 따라서 현재 depth 좌표는 로봇 파지 좌표로 승인하지
않는다. Astra 브리지는 진단 후 다시 시작했으며 8022 카메라 8 응답은 HTTP 200이다.

### 3. 비동작 경로 계획

- [x] 접근, 하강, 파지, 상승, 이동, 투입, 복귀 순서를 정의했다.
- [x] 변환/높이/작업범위/IK/관절 제한 중 하나라도 없으면 waypoint를 만들지 않는다.
- [x] 로봇 명령을 보낼 수 없는 JSON dry-run 결과만 저장한다.
- [x] 불가능하거나 위험한 경로의 거부 사유를 기록한다.
- [ ] 실측 보정 후 IK 해와 관절 제한을 계산·검증한다.

### 4. 안전 제어 API

- [ ] 읽기 전용 상태와 dry-run endpoint를 먼저 제공한다.
- [ ] 실제 실행 endpoint는 환경 설정과 사용자 승인 토큰 없이는 비활성화한다.
- [x] 수동 보정용 텔레오퍼레이션에 시작 자세 게이트, 1도 상대 이동 제한,
  30 Hz 제어율, 180초 자동 종료를 추가했다.
- [ ] OpenClaw 작업 실행용 단일 작업 잠금, 타임아웃, 취소, 단계별 상태 기록을 구현한다.
- [ ] 모터 명령 전 마지막 장면/자세 재검증을 강제한다.

### 5. OpenClaw 연결

- [ ] 사용 중인 컴퓨터와 Jetson 중 OpenClaw 실행 위치를 결정한다.
- [x] 외부 SOARM 예제 구조를 검토하고 읽기 전용 최소 기능만 로컬 초안으로 만들었다.
- [x] 현재 초안은 `inspect_scene`, `plan_transfer`만 제공한다.
- [x] 입력 작업은 정확히 `A`, `B`, `C`만 허용한다.
- [x] 임의 명령과 직접 관절값 입력을 받지 않으며 실행 스크립트도 없다.
- [ ] 보정·IK·정지 경로 검증 뒤에만 `execute_transfer`, `stop_robot`를 별도 설계한다.

### 6. 검증 순서

- [ ] 시뮬레이션 또는 디지털 트윈 dry-run
- [ ] 모터 전원 없이 명령 생성 검수

- [ ] 저속 단일 waypoint 실제 시험
- [ ] 전체 A 작업 1회 감독 시험

## 사용자 도움이 필요한 시점

다음 항목은 자동으로 추정하지 않고 사용자에게 요청한다.

1. 각 ArUco ID가 무엇을 의미하는지 불명확할 때
2. 마커 실제 한 변 길이 또는 작업대 실측 거리가 없을 때
3. 약통/바구니의 정확한 파지·투입 높이가 필요할 때
4. 물리적 작업영역 정리와 로봇 시작 자세 설정이 필요할 때
5. 실제 모터 시험 전 전원차단 수단과 현장 감시 확인이 필요할 때

## 현재 상태

- raw 천장 프레임에서 ArUco ID 0~6이 모두 검출되었다.
- A/B/C 실시간 뚜껑 중심과 바구니 좌표가 계산되었고 오버레이로 확인했다. X 표시는 사용하지 않는다.
- `openclaw_aruco` 읽기 전용 검사기, fail-closed 계획기, OpenClaw 스킬 초안이 생성되었다.
- 자동 테스트 15개가 통과했다.
- A 계획 결과는 `BLOCKED_SAFETY_CONFIG`, waypoint 0개, 실행 권한 없음으로 기록되었다.
- 실제 모터 동작, 추론, 토크 변경은 실행하지 않았다.
- 동기화 RGB-D 재검사 결과 약 21.1 mm의 작업대 좌표 fit 오차가 있어 depth를 바로 사용하지 않는다.
- 수동 보정 전 읽기 전용 관절 비교에서 리더/팔로워의 어깨 회전 차이 5.89도,
  손목 회전 차이 7.08도가 확인되었다. 3도 시작 게이트를 통과하지 못하므로
  텔레오퍼레이션은 시작하지 않았다.
- 다음 작업은 현장 도움을 받아 TCP를 정의하고, 독립된 접촉점으로 `T_B_W`, Z 높이, 작업범위를 실측하는 것이다.
- 기존 60회 데이터 전체를 현재 장면/자세와 대조한 결과 A 에피소드 10이 가장 가까웠다.
  A 약통 픽셀 오차는 2.236 px이고 시작 자세는 손목 회전만 엄격 게이트를 넘었다.
- A 에피소드 10의 명령을 20 Hz, 몸체 0.5도/그리퍼 1.0 이하 단계로 분할한
  54.85초 dry-run 경로를 만들었다. LeRobot 정규화 범위를 강제하며 실행 권한은 없다.
- 실제 동작 전에는 현재 장면 해시/관절 재검증, 단일 실행 잠금, 타임아웃, 정지 경로,
  사용자의 현장 전원차단 준비 재확인이 필요하다.

### 2026-10-06 읽기 전용 연결 사전 점검

- LeLab 8022의 health는 정상이고 텔레오퍼레이션·추론·녹화·보정은 비활성으로 확인했다.
- 로봇 설정의 카메라 이름/인덱스는 ceiling_vertical=8, ceiling_oblique=4,
  end_effector=6이다. `/available-cameras`에서 열린 장치는 2와 8뿐이어서
  설정된 4와 6은 현재 사용 불가로 보고한다. 이 목록은 프레임 실시간성까지
  검증하지 않는다.
- `openclaw_aruco/check_live_readiness.py`와 초안 스킬 wrapper가 LeLab의
  허용된 GET 상태만 읽고, 카메라/보정/FK 차단 사유를 fail-closed 보고한다.
- 최종 점검 결과 `outputs/openclaw_aruco/live_readiness_v2_20261006.json`은
  `BLOCKED_FOR_MOTION`, `motion_authorized=false`, `robot_commands_sent=0`이다.
- 현재 8022 텔레오퍼레이션의 몸체 시작 자세 게이트는 15도로 보고되어,
  앞서 검수한 3도 설정과 다르다. 이 값이 언제/왜 바뀌었는지 확인하기 전에는
  안전장치로 간주하지 않는다.
- 이 컴퓨터에는 OpenClaw CLI/Gateway가 설치·연결되어 있지 않다. 따라서 현재
  연결은 스킬 초안과 읽기 전용 사전 점검 단계이며, 실제 OpenClaw 제어 또는
  10초 로봇 시험은 시작하지 않았다.
